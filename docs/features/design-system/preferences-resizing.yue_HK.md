# 可調整大小的偏好設定視窗

偏好設定保留自訂標題列，並啟用原生可調整大小邊框。即使呼叫端提供視窗樣式，仍然可以拖曳邊緣或角落改變大小。分頁列、搜尋欄、可捲動內容及會換行的底部按鈕保留原有操作。

## 大小及顯示器變更

- 首次開啟為 780 × 640 個裝置獨立像素，一般最小大小為 640 × 480。
- 關閉時，大小以裝置獨立像素儲存到本機設定的 `preferences_width` 及 `preferences_height`。再次開啟會還原大小，並以父視窗為中心。
- 空白、格式錯誤、非正數或過大的設定會使用預設值。數值會先檢查，之後才按顯示比例換算。
- 大小及位置限制於所選顯示器的可用工作範圍，不會佔用工作列。顯示器特別細小時，最小大小會配合實際可用範圍。
- DPI 變更會使用作業系統建議的位置及大小，再套用工作範圍限制。內容不再透過 `Fit()` 重設整個視窗的大小。
- 分頁容器及外層卡片可以獨立縮小，內容由分頁捲動處理。這不代表每一行設定的換行效果都已驗證。

這項設定只儲存視窗大小，不會加入設定值、標籤、搜尋字串或個人用語內容。寫入設定失敗會經現有警告記錄回報，不會在銷毀視窗時拋出例外。

## 驗證

### 不讀取內容的幾何診斷

明確啟用現有 `BAMBU_AUTOMATION=1` 後，目前使用者的本機自動化管道接受 `preferences_geometry`，而 `arguments` 必須是空物件。只提供本機能力的監聽器會拒絕這項操作；其他多餘參數亦會被拒絕。現有分派器會在 UI 執行緒執行，並不開啟偏好設定，也不改變大小、設定、可見狀態或擷取保護。受保護的偏好設定視窗不應啟用一般排版傾印。

版本 1 結果包含 `kind: preferences-geometry`、`state` 及 `roles`。固定角色為 `dialog`、`content_card`、`book`、`search`、`tab_strip` 及目前頁面的 `viewport`。建構時直接提供已知物件指標，並以弱參照保存，不會按視窗名稱搜尋或列舉子項。頁尾是排版器而非視窗，因此不會回報。視窗已關閉或正在銷毀時，結果為 `unavailable` 並沒有角色資料；個別角色不存在時為 `unavailable`，正在銷毀時為 `destroying`，非 UI 執行緒呼叫則為 `wrong_thread`。

可用角色只回報螢幕矩形、客戶區與最小大小、DPI、顯示與啟用狀態，以及是否位於父項客戶區內。頂層視窗的包含結果為 null，因為擁有者並非其排版容器。這只描述幾何關係，並非隱藏或可捲動內容的裁切判定。不會讀取或輸出標籤、名稱、值、輔助功能文字、像素、路徑、個人用語或憑證內容。原始碼、執行檔雜湊、程序身分及擷取保護讀回結果須記在外部驗證紀錄。整個視窗的擷取排除保護維持不變。

`node tests/preferences_geometry_probe.test.mjs` 使用中性視窗替身編譯實際模組及分派准入程式，檢查頁面選擇、大小變化、父項包含關係、隱藏／銷毀／不存在角色、執行緒、權限及多餘參數。內容與子項存取會觸發測試陷阱。`--privacy-mutant` 加入子項列舉，`--geometry-mutant` 偽造包含結果，兩者都必須失敗。這些只是補充測試，並非原生視窗證據。實際驗證仍須綁定確切原始碼及執行檔，測試一般與最小大小並保留保護讀回結果；幾何資料不能證明字體、顏色、文字溢出或完整語言／主題／DPI 矩陣。

`node tests/native_preferences_geometry.test.mjs` 會編譯並執行實際幾何輔助程式，涵蓋七組情境：儲存大小、損壞設定、保留使用者大小、DPI 換算、移除顯示器及工作列邊界、負座標顯示器，以及小顯示器與最小大小限制。三項原始碼變異測試會拒絕移除原生縮放、DPI 限制或大小儲存的修改。基準選項會確認舊建構函式樣式未能通過。

以上屬原始碼及非視窗測試。實際拖曳、鍵盤操作、重新開啟後保留大小、跨顯示器及 DPI 變更，以及最小大小下的英文、廣東話和雙語排版，仍須使用真正編譯的應用程式驗證。現有 `native_preferences_atlas.test.mjs` 在本次基準及目前原始碼都有四項失敗，不能聲稱其歷史指紋檢查已通過。
