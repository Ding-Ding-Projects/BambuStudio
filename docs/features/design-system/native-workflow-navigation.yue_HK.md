# 原生工作流程導航

原生 notebook 將 Prepare、Preview、Print 同 Monitor 投影至前置工作流程群組。`Notebook::SetWorkflowPages(prepare, preview, print, monitor)` 只改視覺順序，永遠唔重排底層頁面，亦唔改現有回呼同指令面板目的地使用嘅數字頁面 ID。其他頁面同尾端操作全部保留。

## 外觀同佈局

Studio Atlas 保留 52-DIP 導航列，使用共用語意表面角色、低色調工作流程群組配 1-DIP 外框、16-DIP 圓角目的地、20-DIP 圖示，同按密度調整嘅 14／13 像素標籤。選取目的地配對 PrimaryContainer 同 OnPrimaryContainer，使用半粗體標籤。懸停同按下用較高同最高中性表面，配中性前景。原有 Button 提供內縮鍵盤焦點環。舒適同緊湊目的地高度遵從共用 40／32-DIP 密度尺寸。原始碼保留目前強調色方案；更廣泛配色更新係獨立改動。

標籤即使靜止時亦預留完整量度半粗體寬度，包括原有本地顯示詞彙轉換。冇固定標籤寬度上限，亦停用收縮。放唔落嘅目的地移入原有 Material 選單表面，保留搜尋、正則建構器、鍵盤導航同焦點還原。目前目的地優先取得可見空間。完整標籤放唔落時，溢出按鈕帶有完整無障礙名稱、選取樣式同標記，選單勾選對應列。

佈局外側縮入 8 DIP，目的地間距 4 DIP。工作流程群組裝飾比目的地矩形向外延伸 1 DIP。正常密度 40-DIP 控件保持垂直置中，外側留 6-DIP 空間。緊湊控件喺同一外框高度內置中。側邊工具保留實測尾端分配。父視窗支援最小視窗仍具權威；細過固定側邊工具加溢出目標嘅寬度，唔會變成新支援視窗尺寸。

## 身分同互動

插入會向前調整已儲存工作流程索引，移除會向後調整。移除工作流程頁面會清除角色。呼叫端取代頁面後必須再呼叫 `SetWorkflowPages`，防止之後無關頁面默默繼承被移除角色。Prepare 同 Preview 可以共用一個內容視窗，同時保留不同頁面索引。

溢出選單綁定弱按鈕身分。啟動時經相同按鈕回呼解析目前頁面索引，唔會喺巢狀選單迴圈開住期間保留過期數字位置。已移除控件唔會啟動另一目的地。導航縮放只隱藏溢出控件，保留仍可見控件焦點，必要時轉移至溢出。可見鍵盤順序跟隨視覺順序。

專案分頁釘選、重排、群組、搜尋、關閉、持久化同相關操作，繼續由 `ProjectTabBar` 同共用 `TabStrip` 負責；呢個 notebook 改動唔會取代或移除佢哋。

選取同導航派發即時生效。250-ms 選取漸變同標記屬裝飾、綁定擁有者而且可中斷；共用動態規則喺減少動態效果下即時完成。冇畫布淡入淡出、延後指令派發或持續裝飾動畫。

## 驗證同剩餘證據

`tests/native_navigation/navigation_layout_tests.cpp` 針對正式、不依賴 wx 嘅 `NotebookNavigation.hpp` 編譯。檢查工作流程投影、無效同重複角色輸入、插入／移除、剛好放入門檻、選取輔助目的地、過大標籤、保留每個目的地、量度寬度不變，以及喺 100%、125%、150%、200% 縮放同 343 個視窗寬度下邊界冇重疊。用儲存庫支援嘅 C++17 編譯器，包含 `tests` 同 `src`；測試定義自身 Catch 入口。整合負責人另外將佢註冊至儲存庫測試建置。

呢個原始碼單元未作原生應用程式建置，亦未喺執行中視窗操作。冇提供畫面擷取、無障礙樹、選單互動、螢幕閱讀器、配色、主題或裁切證據。必要已建置產物矩陣仍待完成：正常同最小視窗、英文／廣東話／雙語、兩種主題、兩種密度同全部支援顯示縮放。原始碼檢查唔能夠證明視覺一致。完整應用程式重設計範圍亦比呢個導航單元廣。

## 共用中性配色，獨立視覺單元

以下預設角色實作 Studio Atlas 瓷白／石板色階，影響原生同其他 `MD3::resolve` 使用者，以及 `StateColor.hpp` 內具名舊中性色別名。呢個係共用預設顏色改動，唔代表餘下各表面組合同控件工作已完成。

| 角色 | 淺色 | 深色 |
| --- | --- | --- |
| Surface | `#f7f9fc` | `#151c25` |
| Surface dim | `#d6e0ec` | `#111821` |
| Surface bright | `#fafcff` | `#3b4c60` |
| Container lowest | `#ffffff` | `#101720` |
| Container low | `#eef2f7` | `#1a2430` |
| Container | `#e7edf5` | `#202d3b` |
| Container high | `#dfe7f1` | `#293849` |
| Container highest | `#d7e1ed` | `#344557` |
| On surface | `#172434` | `#e8eff8` |
| On surface variant | `#46576a` | `#b9c8da` |
| Outline | `#6d7e94` | `#899caf` |
| Outline variant | `#c4d0df` | `#43566a` |

淺色外框比最初參考 `#718298` 稍深：原本同最高容器配對對比係 2.969:1，實作 `#6d7e94` 係 3.137:1。必要邊界至少要 3:1。柔和 outline-variant 仍只係裝飾分隔，唔作必要控件唯一識別。主要同輔助文字喺兩種主題所有預設中性表面上都達 4.5:1。呢啲係原始碼顏色計算，唔係實際繪畫狀態層或使用者自選顏色量度。

`StateColor` 仍接受歷史原始淺色 RGB 值作相容。每個相容映射輸出，喺重複深色轉換下都係固定點。返回淺色時，目前語意中性色角色優先於共用同一深色色調嘅歷史淺色別名，避免反向映射只按數字鍵順序復活舊預設。獨立 surface／bright 鍵亦保留轉換角色。

六個 Brand 強調色角色、Preview／Device 強調色、錯誤／反向角色、使用者種子產生器、密度尺寸同外觀登記保持不變。已儲存元素同預設覆寫唔會重寫或遷移。現有／預設相容集合以外嘅任意 RGB 值保持不變。同以前一樣，純 RGB 相容路徑無法分辨刻意等於已知預設嘅自訂顏色同預設本身；呢項改動唔會聲稱做得到。

執行 `node --test tests/native_navigation/neutral_palette.test.mjs`，可跑九個針對性原始碼合約同顏色算術案例。測試解析正式檔案真實常數同映射項目，檢查兩種主題、中性色層級、對比、正向／反向註冊、歷史相容同深色冪等性，先拒絕刻意低對比同重複映射變更，再檢查原始配色。窄範圍指紋保護未改強調色解析／產生器原始碼。檢查唔會執行 wxWidgets，亦唔證明原生主題切換、已持久化使用者覆寫繪畫或畫面擷取。

呢套配色保留喺獨立視覺提交，與導航提交 `624e2ed52e2fe7afcb91961fcaefe9bb201ba15e` 分開。經審閱還原配色提交，會還原三個共用顏色檔案、呢篇文章新增部分同針對性測試，唔移除工作流程導航 API。還原整個導航提交唔係純設計還原，因為亦會移除 Print 整合依賴嘅排序同溢出行為。中央設計改動帳冊會喺整合後記錄確切可獨立還原配色提交。
