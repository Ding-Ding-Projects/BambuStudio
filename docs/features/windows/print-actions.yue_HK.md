# 打印盤操作同材料映射

準備同預覽操作欄分開提供 **Slice plate**、**Slice and Print**、**Slice and Send** 同 **Print plate**。兩個組合操作都會檢查版本、材料同打印盤，而且只處理當前打印盤，即使普通 Slice 按鈕設定為 Slice all 都一樣。**Slice and Print** 成功切片後開啟原有打印機選擇同打印設定；**Slice and Send** 開啟原有傳送對話框，確認後只傳送檔案，唔會開始打印。打印機選擇同最後確認都保留。操作欄喺較窄畫面會換行；即使符號字型未能載入，選項按鈕仍會顯示文字箭嘴。

每個後續操作只會執行一次，並綁定打印盤、請求批次同原生切片批次。另一個切片要求、取消、切片失敗或未開始、打印盤或項目被替換，以及打印盤結果改變，都唔會開啟後續對話框。成功而且未改變嘅切片可以重用；開啟任何設定對話框之前都會清除待處理操作。材料映射改變會令舊切片失效，並返回準備畫面，除非用戶選擇 **Swap and reslice**。

Custom material 頁面保留拖放，新增材料選擇器及 **Move to left nozzle**、**Move to right nozzle**。**Swap groups** 交換左右噴嘴組供檢查，保留每種材料嘅流量選擇。目標冇相容噴嘴，或者無法保留該流量選擇時，會喺改動任何組之前拒絕交換。**Swap and reslice** 只會喺交換獲接受並通過噴嘴驗證後要求重新切片。呢啲係項目及打印盤選擇，唔會改動進行中嘅實體打印或打印機預設。

打印設定喺每種材料目前嘅左／右噴嘴卡旁加移動按鈕。移動保持待定，直到選擇 **Swap** 或 **Swap and reslice**。有移動待定嗰陣，**Send** 會保持停用，材料訊息同停用按鈕嘅提示都會講明要用 **Swap** 套用移動，或者復原佢哋。每次移動或者復原都會即刻重新檢查對話框，所以復原最後一個移動之後，只要打印機檢查容許，**Send** 就即刻可以再用。兩個操作都會設定目前打印盤嘅 Custom 映射，令舊切片失效並返回 Prepare。**Swap and reslice** 使用同 Prepare 按鈕一樣嘅已檢查 Slice and print 操作。只有目前重新切片成功後先重開打印設定，提交仍需要最後按 **Send**。原有打印選項保留喺重用對話框及儲存設定；噴嘴相關映射會按新切片重新計算。每個打印選項列喺所有顯示縮放下都起碼同佢個開關一樣高，縮放改變時會重新調整大小；Timelapse 儲存位置按鈕會用返該列嘅主題表面顏色。

每次建議移動都核對已安裝噴嘴容量、材料／噴嘴相容性同目標噴嘴可打印範圍。不可用操作會停用並顯示原因。套用待定映射時會再按目前打印盤核對，避免打印設定開啟期間更換打印盤或預設而套用過時分配。

每次開啟打印設定都會做呢啲檢查。檢查期間先會將建議分配寫入打印盤，完成後會將打印盤嘅墨水映射模式、墨水映射、噴嘴映射同容量映射原封不動放返，原本有就放返原值，原本冇就保持冇。檢查唔會經過打印盤嘅映射模式設定函數，因為實際模式一改變，嗰個函數就會清除三個映射。所以開啟打印設定唔會改動打印盤，亦唔會令佢嘅切片失效。**Swap** 會為每種材料儲存檢查認可嘅噴嘴容量類型：新噴嘴嘅類型，或者喺混合噴嘴上保留材料自己嘅類型。

打印設定會檢查準備傳送嗰個打印盤（**Print all** 就檢查每個打印盤），而唔係剛好係目前嗰個。冇可打印物件嘅打印盤會顯示為空打印盤。有物件但切片已經失效嘅打印盤會顯示要重新切片。單一打印盤嘅訊息後面會另起一行，顯示 **Slice again** 文字按鈕。佢可以用鍵盤聚焦，撳落去會關閉打印設定，再執行同一個已檢查嘅 Slice and print 操作。訊息同按鈕文字係兩個獨立嘅翻譯字串，唔會砌埋做一個標籤，所以雙語模式會分別顯示兩者嘅廣東話。**Print all** 嘅訊息會講明係邊個打印盤。兩種情況 **Send** 都會保持停用。

打印設定亦有一行「快速開印模式」，反映同名嘅流程選項。切換會寫入流程預設，打印板需要重新切片，由上面嘅「重新切片」路徑處理；開啟時熱床調平、流量校準同噴嘴偏移校準會強制關閉，任務以全部準備旗標關閉傳送。請睇[快速開印模式](express-print-mode.md)。

儲存嘅自動映射偏好屬於所選打印機預設。新項目只會喺重設後套用。之後更換打印機時，只有項目仍屬於新項目流程，而且全部打印盤繼承項目模式，先會再套用偏好。明確選擇項目映射或匯入 3MF 設定會清除呢種擁有權。明確打印盤模式，包括 Custom，同樣優先。手動材料分配絕對唔會單憑打印機偏好重新建立。

匯入選單公開 Model Creator。命令調色盤索引相同選單命令。佢嘅驗證 STL 到達 `Plater::load_files` 只有在對話框嘅 **Add to plate** 操作之後。

聚焦 C++ 迴歸覆蓋儲存偏好優先同單次 slice continuation 謂詞。一個完整 Windows 構建、原生交互捕獲、真實打印機設定同硬件打印保持未驗證直到那啲檢查對抗構建應用程式執行。

## 取消同非同步通知

原生進度、中途完成同最後完成通知會帶有切片批次。舊批次通知會喺停止工作執行緒之前被忽略，唔會取消較新切片。普通按鈕狀態更新唔會清除待處理操作。明確切片要求會先處理，之後先切換預覽，避免預覽嘅自動切片搶先開始。

通知上嘅取消按鈕只會提出合作式停止要求，介面仍然可以回應，完成之前顯示 **Canceling slicing...**。工作執行緒未放開打印資料之前，唔會開始新切片或者重用嗰份資料。逾時唔會令仍然運行嘅工作執行緒被分離。模型、設定更換同關閉程式仍然要等資料擁有權釋放；無法即時中斷嘅幾何運算可能令呢幾種操作需要等候。

## 驗證狀態

`tests/send_print_readiness_test.cpp` 會執行打印設定嘅打印盤狀態、待定移動閘、噴嘴容量類型同打印盤快照決定（`node --test tests/send_print_readiness.test.mjs` 會編譯同執行佢）。`node --test ui-md3/tests/send-dialog-stale-slice.test.mjs` 會鎖定佢哋嘅接駁、背景處理計時器綁定、**Slice again** 按鈕同 Timelapse 選項列，並檢查每個合約都會拒絕佢鎖定嘅缺陷。`language_mode_tests` 入面嘅雙語登記表案例（`tests/language_mode/bilingual_registry_tests.cpp`）會實際執行，證明點解訊息同 **Slice again** 要分開做兩個標籤：分開嘅時候各自都搵到廣東話，砌埋做一個標籤就一個都搵唔到。

C++ 測試目標係 `print_workflow_tests`。原生通知順序、工作執行緒擁有權同負面變更檢查使用 `node tests/print_workflow/slice_lifecycle_source_tests.mjs`。原始碼檢查唔代表執行緒時序或者畫面已經驗證。

今次修改未有喺本機執行產品建置、測試、切片或者畫面擷取。GitHub 託管嘅 Windows 驗證仍然要編譯程式、執行上述測試、檢查成功／取消／重試同舊通知情況，並驗證英文、廣東話、雙語、光暗主題、支援縮放比例同最窄畫面。驗證必須喺最後硬件打印確認之前停止。

C++ 目標可直接執行，或喺已設定嘅構建目錄執行 `ctest -R ^print_workflow_tests$ --output-on-failure`。案例涵蓋儲存偏好優先次序、單次 Print／Send 派發、過時取消通知、原生／請求批次改變、替換打印盤、失敗結果同明確取消。來源負面檢查要求：拒絕舊通知先於停止工作執行緒；完成通知帶身分；活動工作者唔能夠被遺棄；用戶取消唔等候或提早聲稱完成；重設先停止再刪除打印盤；明確派發先於預覽自動切片。兩條回歸路徑仍須喺託管 Windows 編譯及執行，實際裝置打印唔屬於驗證範圍。
