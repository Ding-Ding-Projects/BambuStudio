# Plate print actions and material mapping

The Prepare and Preview action bar offers **Slice plate**, **Slice and Print**, **Slice and Send**, and **Print plate** separately. Both combined actions use the same version, material, and build-plate preflight as Slice plate and always target the current plate, even when the ordinary Slice button is set to Slice all. **Slice and Print** opens the existing printer-selection and print-setup dialog after a successful slice. **Slice and Send** opens the existing transfer dialog and sends the output only after confirmation, without starting a print. Device selection and final confirmation remain explicit. The action row wraps at narrow widths; option buttons retain visible text chevrons even when the optional symbol font is unavailable.

Each continuation is one-shot and bound to the requested plate, request generation, and native slicing generation. A different slice, cancellation, failed or unstarted slice, plate or project replacement, or a changed plate result prevents either setup dialog from opening. Both combined actions can reuse a successful unchanged printable slice without waiting for another completion event. The pending action is cleared before either dialog appears. A changed material mapping invalidates the sliced result and returns to Prepare unless the user chose **Swap and reslice**.

The Custom material page retains drag-and-drop and adds a material selector with **Move to left nozzle** and **Move to right nozzle** controls. **Swap groups** exchanges the two nozzle groups for review while preserving each material's flow choice. If the destination has no compatible nozzle or cannot represent that flow choice, the swap is rejected before changing either group. **Swap and reslice** requests a fresh slice only after an accepted exchange passes nozzle validation. These are project and plate choices; they do not change an active physical print or the printer's default settings.

Print setup also places a move button for each material beside its current left or right nozzle card. Moves remain pending until **Swap** or **Swap and reslice** is chosen. While a move is pending, **Send** stays disabled, and the material messages and the disabled button's tooltip say to apply the moves with **Swap** or undo them. A move or its undo re-checks the dialog at once, so undoing the last move gives **Send** back as soon as the printer checks allow it. Both actions set the current plate's Custom mapping, invalidate its old slice, and return to Prepare. **Swap and reslice** invokes the same checked Slice and print action as the Prepare button. Print setup reopens only after a successful current reslice, and submission still requires the final **Send** click. Existing print options remain in the reused dialog and its saved option settings; nozzle-dependent mapping is recalculated for the new slice. Each print option row is at least as tall as its switch at every display scale and is resized when the scale changes, and the Timelapse storage-location button takes the row's theme surface.

Each proposed move is checked against installed nozzle capacity, filament/nozzle compatibility, and the target nozzle's printable area. An unavailable move is disabled with a visible explanation. Applying the pending map repeats those checks against the current plate, so a plate or preset change while print setup is open cannot publish a stale assignment.

The checks run each time print setup opens. They write the proposed assignment to the plate only while they run, and then put back the plate's filament map mode, filament map, nozzle map and volume map exactly as they were, present or absent. They never go through the plate's map-mode setter, which clears all three maps whenever the effective mode changes. Opening print setup therefore leaves the plate unchanged and cannot discard its slice. **Swap** stores, for each material, the nozzle volume type the check approved: the new nozzle's type, or the material's own type on a hybrid nozzle.

Print setup checks the plate it is about to send, and every plate for **Print all**, rather than whichever plate is current. A plate with no printable objects is reported as empty. A plate with objects whose slice is no longer valid is reported as needing a new slice. For one plate the message offers **Slice again**, which closes print setup and runs the same checked Slice and print action. For **Print all** the message names the plate. **Send** stays disabled in both cases.

A saved automatic mapping preference belongs to the selected printer preset. A fresh project applies it only after reset. On a later printer change, the preference applies only while the project is still owned by that fresh-project path and every plate inherits the project mode. An explicit project mapping choice or imported 3MF settings clear that ownership. An explicit plate mode, including Custom, also takes precedence. Manual material assignments are never reconstructed from a printer preference alone.

The Import menu exposes Model Creator. The command palette indexes the same menu command. Its validated STL reaches `Plater::load_files` only after the dialog's **Add to plate** action.

## Cancellation and asynchronous events

Native progress, intermediate completion, and final completion notifications carry their slicing generation. A final notification from an older run is rejected before it can stop the current worker or consume a newer continuation. Status-only button refreshes do not cancel pending output. The explicit slice action is handled before Preview selection, preventing Preview's automatic slice from racing the requested action.

The notification's Cancel action requests a cooperative stop and leaves the interface available while the worker exits. The status says **Canceling slicing...** until completion; a request is not reported as a completed cancellation. New slicing and plate-context reuse remain blocked while the worker owns the mutable print data. A worker is never detached after a timeout and allowed to write into reused or destroyed data. Model/configuration replacement and shutdown still wait for exclusive ownership; a non-interruptible geometry operation can therefore delay those particular operations.

## Verification

The focused C++ target is `print_workflow_tests`, with cases for saved-preference precedence, one-shot Print/Send dispatch, stale cancellation events, changed native/request generations, replacement plates, failed results, and explicit cancellation. Run its executable or `ctest -R ^print_workflow_tests$ --output-on-failure` from the configured build directory.

`tests/send_print_readiness_test.cpp` executes the plate status, pending-move gate, nozzle volume type and plate snapshot decisions of print setup (`node --test tests/send_print_readiness.test.mjs` compiles and runs it). `node --test ui-md3/tests/send-dialog-stale-slice.test.mjs` pins their wiring, the background-process timer binding and the Timelapse option row, and checks that each contract rejects the defect it pins.

Run `node tests/print_workflow/slice_lifecycle_source_tests.mjs` for production-source contracts and their negative mutations: event rejection must precede worker stop, completion must carry identity, live workers must not be orphaned, user cancellation must not wait or claim early completion, reset must stop before deleting plates, and explicit dispatch must precede automatic Preview slicing. These source checks supplement native evidence; they do not prove thread timing or rendered layout.

This change was prepared without running local product builds, tests, slicing, or captures. GitHub-hosted Windows verification must compile the application and both regression routes, exercise success/cancel/retry and stale-event delivery, and inspect English/Cantonese/bilingual action controls at normal and minimum widths in both themes and supported scales. Stop before final hardware-print confirmation. Actual device printing is outside this verification scope.
