# 非同步 STL 替換提案

狀態：未完成設計，未實作或驗證。源碼檢查版本為 `23d01afd3d53a3f7d5dcc42db5885281730bca31`。冇本機執行。

## 範圍同觀察到嘅行為

首個候選只應涵蓋單一體積嘅普通 STL 替換。重新載入批次、STEP 對話框、OBJ 顏色回呼同專案匯入，喺獨立設計之前保留原有行為。

`Plater::priv::replace_volume_with_stl` 喺建立 `BusyInfo` 之前讀取並正規化獨立模型。重新載入嘅短非 OBJ 區塊喺讀檔之前銷毀 `BusyInfo`。兩條路徑之後都修改即時模型並更新 GUI 狀態。令忙碌框架有動畫，唔會令同步工作變得有回應。

`JobNew::process` 同 GUI 執行緒 `finalize`，透過現有 `PlaterWorker<BoostThreadWorker>`，提供獨立匯入接點。呢個工作器唔會自動取得舊有 `Jobs::before_start` 切片互斥保障。

## 建議擁有權邊界

研究喺 `BackgroundSlicingProcess.cpp/.hpp` 加入只能移動嘅閒置保留權：

1. 只喺 `STATE_INITIAL` 或 `STATE_IDLE`，而且冇待處理 UI 工作時用 `try_lock` 取得。爭用、進行中工作，以及已完成但未收定狀態都不可用。
2. 將保留權綁定操作身分、原生世代、打印同打印板。喺任何回呼之前釋放 mutex，同時保留保留權旗標。
3. 喺 `start()` 建立執行緒或者狀態轉換之前，以同一 mutex 檢查旗標。保留權透過中央 API 阻止新啟動。
4. GUI 端喺獨立匯入同套用結果期間持有保留權。工作器接收不可變輸入，只擁有自己嘅獨立結果。
5. 只釋放相符保留權。仍需要非阻塞釋放同擁有者銷毀協定；會等 mutex 嘅解構器不可接受。

唔可以將可選工作器觀察當成租約。唔好跨模型套用、回呼或者再次取得 mutex 嘅方法持有 mutex。唔好透過可能等待嘅 `stop()` 取得保留權，亦唔好將已請求取消視為已完成取消。首個設計唔會收定 `STATE_FINISHED` 或 `STATE_CANCELED`。

### 獨立反駁：只排除啟動仍不足夠

源碼審查發現建議啟動旗標未覆蓋嘅額外修改路徑：

- `BackgroundSlicingProcess.hpp:138` 嘅 `set_current_plate`，冇 mutex 或世代增量就直接賦值 `m_current_plate`。只比較最終指標會漏掉匯入期間切走再切返嘅打印板變化。
- `BackgroundSlicingProcess.cpp:159` 嘅 `select_technology` 可以呼叫 `reset()` 並替換 `m_print`。保留權唔可以喺呢個變化後仍當成有效擁有權。
- `BackgroundSlicingProcess.cpp:609` 嘅 `reset`，喺建議保留權合約以外增加原生世代並令步驟失效。

因此，只檢查 `start()` 並不足夠。實作前須定義由擁有者持有嘅保留狀態，喺每條相關打印板、技術、重設同模型修改路徑明確失效。釋放唔可以永久遺留旗標，亦唔可以排入喺銷毀後仍帶原始擁有者指標嘅回呼。失效必須單調，切走再切返都唔能恢復舊請求有效性。呢個係未解決設計要求，唔係目前源碼提供嘅 API。除呢項擁有權工作之外，仍需要完整修改版本或者等效已驗證狀態合約。

## 目標驗證仍未解決

GUI 完成處理必須驗證弱擁有者、目前操作身分、精確模型／物件／體積身分，同每項相關目標狀態，先至建立一次復原快照同套用結果。向量索引同原始指標唔能跨非同步間隔充當身分。

`ModelObject` 同 `ModelVolume` 繼承 `ObjectBase`；復原快照時間戳唔係完整修改版本。替換會讀取設定、轉換、來源偏移及轉換旗標、體積類型／材料、四種表面註記、用作打印床定位嘅物件幾何同同層體積，以及重投影嘅 SLA 點／孔。實例、工作區替換同待處理延續狀態亦須明確處理。不完整嘅手寫指紋不足夠。

現有 cereal 序列化使用特別包裝器並包含可變幾何快取。其位元組相等性同 GUI 成本，尚未證明適合作驗證合約。喺 GUI 執行緒完整序列化網格，可能重製回應速度問題。呢度唔聲稱有完整而低成本嘅驗證機制。

## 必須審查同託管證據

實作之前，獨立反駁保留權取得／釋放、中央啟動排除、重入、擁有者銷毀，同目標驗證完整性。模型、GUI 同 GL 套用留喺 GUI 執行緒；已驗證套用期間不得有巢狀事件迴圈或者模態互動。

託管驗證必須展示實際慢匯入期間嘅心跳進度、取消後唔會再套用、過時目標／工作區拒絕、擁有者關閉、匯入例外、恰好一次復原快照、保留轉換／設定／註記，以及正確場景更新。分開記錄匯入同 GUI 最終處理時間。獨立匯入檢查通過，唔代表最終處理有回應。
