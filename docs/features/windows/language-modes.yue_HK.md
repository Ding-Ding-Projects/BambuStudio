# 英文、香港粵語同雙語模式

## 行為

Windows 分支定義咗三個標準用戶介面模式識別符：

| 模式 | 識別符 | 展示方式 |
|---|---|---|
| 英文 | `en` | 分支嘅英文用詞（墨水同墨水機） |
| 廣東話（香港，預覽版） | `yue_HK` | 每個抽取訊息嘅香港粵語，以英文用詞作為後備 |
| 英文 + 廣東話（香港，預覽版） | `bilingual_en_yue_HK` | 英文先行，粵語會以同一行、下一行或者工具提示形式，出現喺下面講到嘅每個介面 |

呢啲係分支嘅基線模式，唔係取代 Bambu Studio 現有嘅語言地區。特別係，正式書寫嘅 `zh_TW` 仍然係一個獨立嘅語言地區，從來唔會被重新標籤為粵語。用連字號嘅相容別名會喺儲存之前，統一換成標準嘅底線識別符。

原生模式解析集中喺 `src/slic3r/GUI/LanguageMode.*`。佢保持格式化、目錄、嵌入式網絡、遠端服務同字型路由各自分開。呢兩個自訂模式使用佢哋本地嘅粵語資源，但向雲端服務同服務語言標頭送出嘅係英文，而唔會洩露 `yue` 或 `bilingual` 識別符到外部服務。

## 粵語目錄

`bbl/i18n/yue_HK/BambuStudio_yue_HK.po` 為當前英文抽取（7,496 個訊息）同英文覆蓋目錄中嘅每個訊息都有一個條目。佢持有 7,658 個條目：993 個人手整理、 6,665 個帶有 `#. review-status: agent-drafted` 嘅條目（少數涵蓋當前原始碼已唔再使用嘅訊息）。`scripts/i18n/Test-LanguageModes.ps1` 會喺某個訊息冇粵語條目時失敗，所以新字串需要喺同一次變更中翻譯。每個草稿條目都通過咗 `scripts/i18n/merge_cantonese_drafts.py` 中嘅機械檢查：

- 佔位符與英文相符，未編號嘅佔位符保持英文順序；
- 換行符同選單助記符會被保留；
- 冇只屬簡體嘅字，亦冇 `glossary.json` 入面嘅禁用詞（例如 `列印`、`印表機`、`專案`、`軟體`、`線材`、`耗材`、`您`、`引數`、`裡`）；
- 句子用書面香港粵語（嘅、係、冇、咗 等等）；
- 冇未翻譯嘅佔位文字，結尾嘅冒號、省略號同問號會保留；
- 對齊：喺 `zh_TW` 目錄有相同訊息嘅參考時，草稿要同參考譯文有相當部分嘅內容字相同，所以掛錯喺另一個訊息嘅翻譯會被拒絕。

草稿條目未經人工審閱。`merge_cantonese_drafts.py --audit` 會重新執行草稿條目嘅每項檢查並喺任何失敗時以非零狀態退出；`--purge` 會移除失敗嘅條目，使佢哋返回翻譯隊列。對齊檢查存在係因為 826 個早期草稿通過咗所有其他檢查，但被附加到錯誤嘅訊息；佢哋被移除並重新翻譯咗。

喺粵語模式中，冇粵語條目嘅訊息會後備到英文覆蓋目錄，所以後備文字使用分支嘅英文用詞而唔係原始字串。

## 原生介面中嘅雙語模式

每個舊版查詢（`_L`、`_u8L`、`_CTX` 同複數形式，全都以 `I18N::finish()` 結尾）會顯示英文並喺 `BilingualRegistry` 中記錄該確切顯示英文嘅粵語。帶有格式佔位符嘅字串會被記錄為範本，所以使用 `format()` 或 `wxString::Format()` 構建嘅標籤會使用相同嘅填充值找到佢嘅粵語。

`BilingualDecorator` 僅喺雙語模式中執行。佢監視視窗嘅顯示並為標籤、按鈕、核取方塊、選項按鈕、群組方塊、段落標題、清單同表格嘅欄標題、工具提示同原生選單項目提供第二語言：

- 單行文字如果喺佈局畀到嘅空間入面放得落，就會顯示成「English · 廣東話」。對話框可以喺螢幕範圍內加大；如果內容仍然放唔落，標籤就維持英文。喺會捲動嘅頁面（每個偏好設定頁、準備側邊欄），只計標籤本身已經有嘅位：頁面唔會跟住對話框變闊，而係捲動，所以標籤一變闊，就會將嗰行尾嘅控制項推出視線以外。
- 放唔落嘅文字維持英文，工具提示會加上「廣東話：…」。
- 換行同多行文字喺英文下方顯示粵語。程式按指定闊度換行嘅標籤（例如每個偏好設定行嘅標題同說明），如果「English · 廣東話」一行放得落嗰個闊度，就咁樣顯示；否則粵語會放喺英文下面，按同一個闊度換行。
- 佈局定咗之後，修飾器會再檢查自己做過嘅嘢：雙語標籤如果被截短、超出上層視窗顯示得到嘅範圍，或者令會捲動嘅頁面需要比佢顯示嘅更闊，就會變返英文，粵語放入工具提示；如果係程式會換行嘅標籤，粵語就放喺英文下面。
- 工具提示喺英文下方顯示粵語。修飾器會記住應用程式自己嘅文字，所以修飾唔會累積。
- 清單同表格嘅欄標題喺欄夠闊時會顯示「English · 廣東話」。欄標題冇工具提示，所以放唔落嘅標題就維持英文。
- 文字欄同搜尋欄嘅提示文字（placeholder）喺欄位夠闊時會顯示「English · 廣東話」，唔夠位就維持英文。
- 鍵入嘅文字、列表值同組合框值永遠唔會被更改。已經自己呈現兩種語言嘅視窗（`apply_localized_text()`）唔會被改動。

設定標籤由 `OG_CustomCtrl` 自己繪製，透過 `I18N::fit_bilingual()` 喺繪製時使用相同嘅規則；標籤欄維持英文嘅闊度，標籤嘅工具提示就帶住粵語描述。Material 選單會喺每個項目嘅第二行顯示粵語。

自己繪畫嘅控制項（分頁列、步驟指示器、開關同類似控制項）同 3D 畫布（ImGui 文字、操作工具同通知）喺繪畫時用同一個規則。通知嘅連結，例如「Restart to install update」或者「Retry」，如果「English · 廣東話」放得落通知嘅一行，就會咁樣顯示，放唔落就維持英文；通知嘅文字本身會喺下面顯示廣東話。

已知限制：程式喺畫面上改寫嘅標籤會變返英文，直到下一輪處理為止，大約每三秒一輪。相機畫面上細細個嘅 LIVE 標記維持英文。

## 文件同更新日誌

`docs/features` 下嘅每篇文章都有一份香港粵語翻譯放喺佢旁邊，命名為 `<article>.yue_HK.md`。佢嘅前置資料記錄咗 `review-status: agent-drafted` 同佢翻譯嘅英文文章嘅 `source-sha256`（英文文字嘅 SHA-256，CRLF 換行符正規化為 LF），而第一行會連返去英文文章。喺粵語模式，指令面板會打開譯本；喺英文同雙語模式，就會打開英文文章。

應用程式內嘅更新日誌會讀取 `changelog.json` 旁邊嘅 `resources/changelog/changelog.yue_HK.json`：一個由每項記錄嘅提交 SHA 對應到粵語文字嘅對照表。英文模式顯示英文記錄，粵語模式顯示粵語（未有譯文嘅記錄就顯示英文），雙語模式兩樣都顯示，粵語喺下面。搜尋會配對任何一種語言，而「複製」同「匯出」會帶走檢視器顯示緊嘅文字。翻譯檔案唔見咗或者損壞，更新日誌會維持英文，唔會變成空白。

`scripts/i18n/check_translated_content.py` 喺以下情況會失敗：文章冇譯本、英文文章喺翻譯之後改過（雜湊值唔再相符），或者更新日誌記錄冇粵語文字。`scripts/i18n/Test-LanguageModes.ps1` 會執行佢；改動文件或者更新日誌之後，推送之前要先跑呢個腳本。

## 嵌入式網頁介面

- DeviceWeb 全部 204 個英文條目嘅鍵都有對應，並會建立一個英文先行嘅雙語版本。
- 舊版本地網頁資源（`resources/web/data/text.js`）全部 281 個英文鍵都有對應。每個標咗 `.trans` 嘅頁面元素都必須用英文表入面有嘅鍵；圖像替代文字（`data-alt-tid`）同輸入佔位符（`data-ph-tid`）亦會跟隨語言模式。喺雙語模式，佔位符放得落欄位就會顯示兩種語言，否則顯示英文，並喺欄位嘅工具提示顯示兩種語言。
- 本地頁面會收到本地網頁語言，包括 `yue_HK` 同雙語模式：設定嚮導、墨水建立同編輯、項目標籤、插件下載頁面同打印機連接頁面。遠端頁面（MakerWorld、登入）就會收到服務語言。
- `fila_manager` 頁面未被翻譯：佢嘅面板永遠唔會被構建，應用程式顯示嘅墨水管理器住喺 DeviceWeb 中。
- Pages／瀏覽器 MD3 原型只會儲存呢三種模式，支援唔會儲存嘅 `lang` 查詢參數覆蓋，並會逐步展開較長嘅粵語文案，保護窄版面。

### 主頁網頁檢視嘅雙語佈局

主頁網頁檢視（`resources/web/homepage3` 加上共用嘅 `resources/web/data/text.js` 目錄）以兩個保護句子完整性同佈局嘅規則呈現雙語模式：

- **僅限全字串標記。** `GetLocalizedTextByKey` 喺元素級別上標記一次 `.trans` 元素。舊版標記從多個 `.trans` 片段組成嘅句子（例如網絡插件橫幅：「Please 」+ 「install」+ 「 the network plugin before logging in」）會被包裹喺 `.bi-group` 容器中：喺雙語模式中，片段會僅英文呈現，`AnnotateBilingualGroups` 為整個句子附加咗一個單獨組成嘅粵語行。如果組成整體嘅任何片段缺少真實嘅粵語翻譯，或粵語等於英文，表面只會顯示英文而唔係交錯地呈現片段式粵語。
- **緊湊、非重疊嘅次要行。** 粵語註解係一個獨立、字體較細嘅區塊（`0.85em`；容器係單行時會用省略號截短，完整文字保留喺 `title` 工具提示）。側邊欄項目（`.BtnItem`）同登入區域用 `min-height`，配合直向 flex 排列嘅 `#LeftBoard`，所以兩行嘅項目同網絡插件橫幅會向下伸展，將選單推開而唔係蓋住佢。喺錯誤橫幅內，次要行保持完整 `--md-on-error-container` 對比度，可能會換行。

屬性同 `innerText` 上下文（圖示 `title` 工具提示、模型搜尋佔位符、確認對話框）使用 `GetCurrentPlainTextByKey`，佢會產生 `English ／ 粵語：Cantonese` 純文字，所以冇標記會洩露到工具提示或對話框。純英文同純粵語模式嘅輸出，同目錄字串逐個字節一樣。

喺繁體中文模式，原生 Windows 標籤會優先使用 Microsoft JhengHei UI，因為捆綁嘅 Roboto 檔案冇包含粵語字形。ImGui 會載入繁體中文字形範圍。英文同其他拉丁字母模式繼續使用以私有方式註冊嘅 Roboto 資源。

## 設定同安裝程式交接

應用程式會將所選模式儲存喺平時嘅 `language` 應用程式設定。「偏好設定」中嘅前三個條目係英文、粵語預覽同雙語；之後會列出每個已安裝目錄嘅原有語言地區。模式變更使用現有嘅重新啟動／重建流程，並保留平時嘅已修改預設確認。

支援嘅安裝程式係未簽名嘅 Squirrel.Windows `Setup.exe` 包。佢冇提供語言命令列開關，亦唔會另外喺登錄檔寫入安裝程式偏好設定：首次啟動使用應用程式嘅持久化 `language` 設定，而全新嘅設定檔會以英文開始，可以從「偏好設定」中選擇粵語或雙語模式。Squirrel 更新會將應用程式數據設定保持喺原位，所以更新唔會重置用戶嘅語言選擇。

安裝程式同更新失敗會喺啟動後使用應用程式嘅當前語言模式報告。安裝程式本身保持語言中立，Squirrel 套件根本冇呢種約定，所以安裝程式永遠唔會假裝接受咗命令列語言值。

## 後備同安全規則

- 缺少原生粵語目錄或未翻譯嘅訊息會後備到英文用詞。
- 空白訊息喺每種模式都維持空白。目錄會用佢嘅標頭（「Project-Id-Version: ...」）回答空白訊息，所以每個直接查目錄嘅地方都會跳過佢；以前粵語模式會將呢個標頭當成每個冇單位嘅數值輸入框嘅標籤。
- 兩個分支目錄喺構建時被編譯：CMake `fork_catalogs` 目標（需要 Python）會將英文覆蓋 PO 同粵語 PO 轉換為 `BambuStudio.mo` 檔案，Git 入面唔會追蹤任何 MO 檔。Windows 工作流會喺打包前使用 `--check` 再次編譯已安裝嘅粵語目錄，所以過時嘅目錄唔會靜靜雞出貨。
- Pages／瀏覽器遇到未知模式會後備到英文，而唔會覆蓋已儲存嘅有效偏好設定。
- DeviceWeb 同舊版本地網絡資源嘅英文同粵語鍵必須完全對應，插值佔位符亦要相符。
- 雙語格式佔位符會喺兩種語言中各別展開，然後兩個展示結合，防止重複或格式錯誤嘅執行時參數。
- 一般文案可以輕鬆簡潔。破壞性操作、隱私、證書、未簽名軟件、致命錯誤同恢復說明就用克制、照字面嘅粵語。

## 驗證狀態

`scripts/i18n/Test-LanguageModes.ps1` 嚴格編譯兩個目錄，執行草稿條目審計同文件及更新日誌檢查，並檢查標準 ID、DeviceWeb 同舊版網頁嘅鍵對應、頁面鍵、佔位符同 ui-md3 語言測試。`scripts/ci/Test-InkTerminology.ps1` 檢查每個目錄中嘅墨水詞彙。呢啲腳本喺推送之前喺本機執行：Windows 工作流只會建置同發佈版本，唔會執行任何測試或者檢查。`language_mode_tests` 涵蓋原生正規化、路由分離、格式前呈現行為同雙語對照表；工作流以 `SLIC3R_BUILD_TESTS=OFF` 設定，所以唔會喺嗰度建置或者執行佢。

此頁面唔聲稱包含雙語修飾器嘅構建已喺執行中嘅應用程式中被驗證。草稿粵語仍然需要獨立嘅人工審閱，最重要嘅係對於安全關鍵嘅打印、帳戶、網絡同破壞性流程。
