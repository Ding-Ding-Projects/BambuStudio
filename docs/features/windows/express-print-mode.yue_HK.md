# 快速開印模式

快速開印模式會跳過 Bambu Lab 打印機每次開印前嘅可選準備步驟，只保留打印需要嘅嘢：加熱、一次歸零、墨水機入墨、清料線同等溫。佢係一個流程選項 `express_print_mode`，分兩部分：開始 G-code 部分同傳送部分。兩部分都只會喺選項開啟時生效；預設係關閉。

## 跳過咩、保留咩

| 快速模式跳過 | 保留 |
| --- | --- |
| 熱床調平（`G29`） | 熱床、噴嘴同（有嘅話）機箱加熱 |
| 抹噴嘴 | 一次歸零（`G28`） |
| 震動（機械模式）檢查同掃描（`M970`、`M974`） | 墨水機入墨（`M620`、`M621`）同之後嘅沖料 |
| 流量（擠出）校準同噴嘴偏移校準 | 清料線或者入墨線 |
| 掃描器、激光、鏡頭、手眼、熱床同打印板偵測（`M972`、`M973`） | 最後嘅等溫同結束準備嘅 `M1002 gcode_claim_action : 0` |
| 開機音樂（`M1006`）同齒輪降噪（`M982.2`） | Z 偏移微調（`G29.1`）、震動抑制（`M975 S1`）同開啟咗嘅第一層掃描 |

快速模式唔會修正第一層。請喺最近已經調平同校準過、打印板冇移動過嘅打印機上使用；呢個模式係用嚟慳時間重複打印，唔係取代調平。H2 系列亦會跳過熱端類型偵測；打印設定對話框仍然會核對噴嘴直徑同類型。

## 選項

選項喺流程設定嘅「其他」頁「特殊模式」組別，「延時攝影」之後。簡單模式下係一個開關，會隨流程預設同項目儲存，可以經設定搜尋同指令面板嘅「喺設定入面搜尋」搵到。切換只會令 G-code 輸出失效，所以下次需要時只會重新輸出，唔會重新切片。

## 開始 G-code 部分

Bambu Lab 開始 G-code 範本（`resources/profiles/BBL/machine/*template machine_start_gcode.json`）喺原本無條件執行嘅段落加咗 `{if !express_print_mode} ... {endif}` 守衛：開機音樂、齒輪降噪、抹噴嘴、震動檢查、各項偵測同 Z 偏移校準。熱床調平、擠出校準同工具頭偏移校準本身已經由打印機韌體用傳送旗標控制（`M1002 judge_flag` 加 `M622 J1` 或者 `J2` 區塊），所以保持不變：傳送部分會關閉呢啲旗標，而佢哋嘅 `M622 J0` 分支仍然會歸零。每個範本開頭亦加咗 `{if express_print_mode}` 註解，令輸出檔案講明點解開頭咁短。

守衛由 `scripts/profiles/express_start_gcode_guards.py` 按每個系列嘅標記表套用。腳本可以重複執行，會拒絕拆開佔位符區塊或者 `M622`/`M623` 配對嘅範圍，逐位元組重新編碼 JSON 字串，並有 `--check` 同 `--render express|normal <file>` 模式。`ui-md3/tests/express-start-gcode.test.mjs` 用自己嘅解析器以兩種模式解析每個範本，如果快速檢視殘留調平、震動、偵測、音樂或者 Z 偏移指令，或者遺失歸零、入墨、等溫、清料線或者完結動作，又或者正常檢視遺失該系列已知嘅指令，測試就會失敗。

冇呢啲守衛嘅自訂開始 G-code 只會得到傳送部分。喺打印機螢幕或者 SD 卡開始、而且喺打印機上開咗調平或者流量校準嘅檔案，仍然會執行嗰啲韌體控制嘅區塊；呢個係刻意保留嘅後路。

## 傳送部分

「傳送打印任務」對話框喺選項最前面顯示「快速開印模式」一行。同其他行唔同，佢唔係每部打印機儲存嘅選擇，而係反映流程預設。切換會經流程設定分頁寫入預設，切片會被標記為需要重新輸出，對話框會報告打印板需要重新切片並提供「重新切片」，所以用一個值切片嘅打印板永遠唔會用另一個值傳送。呢一行只會喺「重新切片」可以用嘅時候生效：即係冇傳送緊嘢時對目前打印板嘅正常傳送。「全部打印」、SD 卡檢視或者傳送中，佢會變灰並顯示提示，保持預設嘅值。

模式開啟時，「自動熱床調平」、「流量動態校準」同「噴嘴偏移校準」會強制關閉並變灰，提示「已被快速開印模式關閉。」；關閉模式後會回復每部打印機嘅儲存值。任務會以全部準備旗標關閉（包括「自動」）傳送，由 `src/slic3r/GUI/SendPrintReadiness.hpp` 嘅 `apply_express_print_mode()` 決定，並由 `tests/send_print_readiness_test.cpp` 執行。延時攝影唔係準備步驟，保留用戶嘅選擇。

多機傳送頁面喺模式開啟時會以熱床調平同流量校準關閉傳送，並將兩個核取方塊變灰。自動化橋接對以模式開啟切片嘅檔案會預設 `bedLeveling` 關閉；呼叫方仍然可以傳 `bedLeveling: true`。

## 時間估算

時間估算器喺遇到 `M622 J1` 區塊入面嘅 `G29` 時，每個檔案加一次準備時間。Bambu Lab 打印機開啟快速模式時，會用固定 60 秒（`EXPRESS_PREPARE_COMPENSATION_TIME`）代替打印機嘅 `machine_prepare_compensation_time`（原廠設定 260 秒）。呢 60 秒代表估算器冇模擬嘅歸零、入墨同清料線；係估計，唔係量度。

## 驗證

呢次改動已驗證：每個改動過嘅編譯單元喺 Linux 上嘅 g++ 語法檢查、`tests/send_print_readiness_test.cpp`（47 個斷言）、`ui-md3/tests/express-start-gcode.test.mjs`、`ui-md3/tests/send-dialog-express-mode.test.mjs`、`ui-md3/tests/send-dialog-stale-slice.test.mjs`、帶 `--require-complete` 嘅廣東話目錄檢查，以及閱讀 X1 Carbon、X1E、P1S、A1、A1 mini、H2D 同 P2S 範本解析後嘅快速開始 G-code。未驗證：MSVC 編譯、執行中應用程式嘅對話框、真實打印機上嘅打印，以及對照真實準備時間嘅估算。分支嘅託管 Windows 編譯係原生判定；聲稱打印機行為嘅發佈說明必須引用一次真實打印。
