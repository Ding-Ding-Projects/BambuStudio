# 發佈啟動畫面藝術（每個發佈新鮮點心）

每個 Windows 發佈寄運一份獨一無二嘅啟動畫面圖像。`resources/images/splash_logo.svg`（94x122 viewBox）嘅打包副本喺 CI 度由工作流執行號重新生成，所以每個發佈嘅安裝程式同便攜 zip 攜帶唯一點心藝術同時倉庫嘅預設濺水檔案永不改變。

## 行為

`scripts/ci/New-DimSumSplash.ps1` 確定性組成一個平面、簡單點心景象喺同一個手繪樣式如預設啟動畫面標記：

- **菜餚**：2-4 項從十八個手創作 SVG 片段嘅庫中冇替換選取：蝦餃、燒賣帶魚卵、蛋撻、春卷、褶皺寶、蘿蔔糕片、風格化雞腳、蛋仔塊、腸粉卷、菠蘿包、糯米雞包裹、芋頭餃、叉燒酥、芒果布丁、芝麻球同雲吞碗。庫係實踐上追加唯一但唔通過契約：添加菜餚改變給定種子繪製咩項目，所以藝術係特製一個種子只係*喺一個庫版本內*。每個生成檔案因此記錄佢嘅種子**同**佢嘅菜餚列表喺 SVG 評論頭，所以任何過去標記可被認定到之後。
- **安排**：菜餚登陸喺左 / 右 / 前位置（前係英雄位置全縮放）；一個較小後位置只出現當第四菜餚被繪製。繪製順序係後、左、右、前所以重疊讀自然。
- **蒸籠**：一個或二層竹蒸籠加上筷子永遠存在所以標記讀作點心一覽。
- **蒸汽**：2-4 個柱帶種子 x 位置、曲率振幅同捲方向。
- **調色盤**：四個溫暖調色盤中嘅一個（`toasted-bamboo`、`golden-hour`、`rosewood`、`jade-morning`）輪流竹色調、包裝/包色調、筷子橙子同蒸汽灰。

## 確定性

所有變異流自純 32 位線性同餘發生器（數值配方常數、5 步預熱）帶 `-Seed` 種子。同種子永遠產生字節相同 SVG；發生器使用冇 `System.Random`、冇時間同冇環境輸入，同數字帶不變文化格式化。種子繪製嘅順序（調色盤、菜餚計數、層級計數、柱計數、菜餚洗牌、位置洗牌、柱參數）係契約一部分，重新排序佢哋改變現有種子嘅藝術。

選擇種子係 GitHub Actions `run_number`，佢也係發佈嘅連續編號嘅基礎，所以藝術係特製任何給定發佈之後。生成 SVG 嵌入一條評論記錄種子、調色盤、菜餚、層級計數同柱計數。

## 佢執行邊度

步驟「為呢個發佈構成唯一點心濺水藝術」喺 `.github/workflows/build_bambu.yml` 執行在構建/安裝步驟已經人口 `install-dir` 之後同 SBOM、便攜 zip 同 NSIS 安裝程式步驟之前，只重寫 `install-dir\resources\images\splash_logo.svg`（打包負載副本）。SBOM 因此哈希寄運檔案，両個構件打包新藝術。步驟記錄選擇調色盤、菜餚、位置、層級計數同柱。

倉庫檔案 `resources/images/splash_logo.svg` 停喺佢嘅預設；本地開發構建使用預設標記。

## 本地重現

```powershell
.\scripts\ci\New-DimSumSplash.ps1 -Seed 123 -OutPath $env:TEMP\splash-123.svg
```

使用發佈嘅工作流執行嘅執行號作為種子重現果個發佈嘅確切濺水。腳本打印選擇變異同輸出字節大小，建立缺失父目錄，拒絕寫任何唔解析為格式良好 XML 嘅野。

## 失敗模式

- 腳本拋出（失敗 CI 步驟）如果組成 SVG 唔係格式良好 XML：前一個負載檔案留冇觸摸喺呢個情況因為驗證發生喺寫前。
- 如果 `install-dir` 仲未存在（步驟順序破壞），腳本建立目錄同構建仍然打包藝術，但應用程式二進制會遺漏；構建/安裝步驟更早失敗係實門。

## 安全考量

發生器取冇外部輸入超過整數種子同路徑，做冇網絡呼叫，同寫單一本地檔案從手創作片段。冇用戶數據、秘密或下載內容涉及。

## 驗證

本地煙霧檢查（執行喺功能登陸）：種子 1、42 同 137 產生格式良好、相互不同 SVG（2152、2762 同 2928 字節），同重現種子 42 產生字節相同檔案（哈希相等）。喺 CI，步驟記錄記錄每個發佈嘅種子同選擇變異。
