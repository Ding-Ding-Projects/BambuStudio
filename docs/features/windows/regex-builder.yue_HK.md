# 正則表達式構建器

每一個本地搜尋介面都可以直接使用同一個完整嘅導引式正則表達式構建器（`RegexBuilderPopup`）：wx 介面使用共用嘅 MD3 `SearchField`，而字型選擇器、通用 ImGui 列表搜尋同組合樹搜尋都會經由 `RegexBuilderBridgeState` 公開一個可用鍵盤到達嘅調整按鈕。兩條路徑都提供分段式標記構建、原始模式編輯器、旗標切換、實時語法反饋、受限嘅樣本文字測試（帶有匹配項同擷取組列表），以及針對應用程式真實正則表達式引擎嘅複製/匯出功能。

## 引擎、方言、旗標、逃逸

- **引擎**：Boost.Regex 1.84 嘅寬字元引擎，搭配 `boost::regex_constants::ECMAScript`，只喺獨立嘅 `bambu-regex-worker` 處理程序裏執行。構建器同所有使用者撰寫嘅搜尋路徑都使用相同嘅 `BoundedRegex` 用戶端（`SearchField::textMatches`、`Search.cpp`、`ObjectDataViewModel.cpp`、`ImGuiWrapper.cpp` 同組合樹篩選器），所以預覽同搜尋唔會喺方言之間偏差。
- **大小寫敏感性**：「大小寫敏感」旗標對應 `boost::regex_constants::icase`（喺大小寫敏感性關閉時新增）。
- **多行錨點**：「多行錨點」旗標清除 `boost::regex_constants::no_mod_m`，所以 `^` 同 `$` 亦都會比對行邊界。預設係關閉嘅。`no_mod_s` 保持設定，所以 `.` 唔會因為多行錨點被啟用就開始比對換行符。
- **整字**：只適用於純文字（非正則表達式）搜尋；喺正則表達式模式裏作者使用 `\b`。構建器會喺旗標旁邊講明呢點。
- **逃逸**：反斜線逃逸 ECMAScript 後設字元 `\ ^ $ . | ? * + ( ) [ ] { }`。「字面值」部分會自動進行呢個逃逸。

## 到達構建器

- 每一個 `SearchField` 都會顯示一個持續嘅尾部 `.*` **正則表達式切換**（純文字係預設；正則表達式模式係一個刻意嘅選擇，亦都會將輸入切換到 Roboto Mono）同一個 `tune` **構建器按鈕**，會開啟浮動視圖。
- 緊湊 ImGui 搜尋行會顯示相同嘅 `.*` 切換加上調整按鈕。橋接會喺兩個方向同步模式、正則表達式模式、大小寫敏感性同整字模式，而唔會擷取 ImGui 擁有者嘅生存期。
- 裝載共用欄位嘅搜尋介面包括：參數搜尋（`Tab.cpp` / `Search.cpp`）、Plater 物件搜尋（`Plater.cpp`）、偏好設定（`Preferences.cpp`）、使用者預設（`UserPresetsDialog.cpp`）、裝置選擇（`SelectMachinePop.cpp`）、多機器管理員（`MultiMachineManagerPage.cpp`）、項目版本歷史紀錄（`ProjectHistoryDialog.cpp` ， 篩選快照列表）、打印主機上傳佇列（`PrintHostDialogs.cpp` ， 佇列搜尋：計數同選擇比對項；列從不隱藏，因為上傳任務 ID 係列索引）同設定檔管理員（`ConfigProfilesDialog.cpp`）。佢哋每一個都會取得相同嘅構建器。ImGui 字型選擇器、通用列表搜尋同組合樹篩選器會使用上述嘅橋接，而唔係一個減少嘅純切換變體。
- **色彩感知搜尋**：帶著色彩嘅列也會按色彩比對。共用幫助程式 `SearchField::colorSearchText(wxColour)` 貢獻 `#RRGGBB <nearest-common-name>`（例如 `#00AE42 green`）到列嘅乾草堆；Plater 物件搜尋使用佢，所以輸入 `green`、`grey`/`gray` 或十六進制值可以尋找使用該墨水打印嘅物件。正則表達式模式自然組合（`^#00` 比對所有深藍色頻道十六進制）。
- 查詢、模式、旗標同模式雙向保持同步：喺欄位裏輸入會即時更新浮動視圖嘅原始編輯器，同浮動視圖裏嘅編輯會重新觸發欄位嘅查詢回呼，所以主機列表會立即重新篩選。
- 浮動視圖係**分頁式嘅**：「構建」裝載導引式部分，而「參考」係內建嘅迷你文件 ， 搜尋點樣運作（純文字預設、旗標、失效安全無效模式、受限評估），每一個標記連同佢嘅完整描述（從晶片使用嘅相同表格呈現，所以文件永遠唔會偏差），做過嘅例子，同 **OpenCode 幫助**：一個按鈕複製描述引擎、當前模式同樣本文字嘅提示詞到剪貼簿並喺佢喺 PATH 時啟動 OpenCode（提示詞永遠唔會去到命令列；應用程式本身唔會將任何野送往任何地方）。

## 浮動視圖結構（`src/slic3r/GUI/Widgets/RegexBuilderPopup.{hpp,cpp}`）

1. **標題 + 引擎標題** ， 命名 Boost.Regex 1.84 嘅寬字元引擎、ECMAScript 語法、隔離嘅受限工作者、`icase` 旗標同反斜線逃逸規則。
2. **模式** ， 原始模式編輯器（Roboto Mono），與擁有欄位嘅查詢雙向同步，加上一個複製到剪貼簿圖示按鈕（`wxClipboard`）。
3. **有效性行** ， 每次按鍵都有實時反饋：主要色「有效模式」（喺有樣本文字時帶有比對計數）或錯誤色訊息，映射工作者穩定嘅正則表達式錯誤代碼到友善嘅描述（不平衡 `[ ]` / `( )` / `{ }`、錯誤計數、無效逃逸、無效向後參考、無效範圍、懸掛量詞、未知類別、太複雜模式）。
4. **旗標** ， 「正則表達式模式」（`.*` 切換）、「大小寫敏感」、「多行錨點」同「整字」複選框。旗標變更會重新觸發欄位嘅正則表達式切換回呼，所以消費者會用共用嘅 `textMatches()` 語義重新執行佢哋嘅篩選。
5. **導引式部分** ， 標籤晶片調色板，每個晶片有解釋性提示；點擊（或 Enter/Space）會喺模式插字符號插入標記，同 `()` / `[]` 風格標記會喺對裏落地插字符號：
   - *字面值*：一個文字輸入加上「新增」，會插入帶著所有後設字元逃逸嘅文字；
   - *字元類別*：`.` `[ ]` `[^ ]` `a-z` `\d \D \w \W \s \S`；
   - *錨點*：`^` `$` `\b` `\B`；
   - *組同交替*：`( )` 擷取、`(?: )` 非擷取、`|`、`\1` 向後參考；
   - *量詞*：`*` `+` `?` `{n}` `{n,}` `{n,m}` 同懶惰變體 `*?` `+?` `??`。
6. **測試模式**（可折疊，預設折疊 ， 漸進式揭露保持浮動視圖緊湊）， 一個受限多行樣本文字輸入，帶著實時比對突出顯示（SecondaryContainer 色調跨度）同一個結果列表，顯示每次比對嘅序數、字元範圍、比對文字，同每個擷取組（`group N: text` / `group N: (no match)`）。

浮動視圖使用 `wxPU_CONTAINS_CONTROLS` 模式（由 `Search.cpp` 嘅 `SearchDialog` 証明）喺短暫快顯內裝載真實子控制。顯示快顯同聚焦其原始模式子係一個操作（`Popup(m_pattern)`）：wxWidgets 喺啟用變更前安裝圍繞實際子嘅焦點追蹤，同佢嘅原生短暫視窗處理程序擁有外部點擊/Alt+Tab 解除。第二個擁有者停用鉤子一定唔好綁定，因為喺焦點進入模式編輯器時會解除快顯。`Esc` 明確解除佢。內容存活喺一個垂直 `wxScrolledWindow` 裏，其高度上限係顯示（符合 800px 高螢幕喺 100、200% 縮放；溢出會滾動）。每次開啟時都會重建浮動視圖，所以色彩、字型同 `FromDIP` 指標每次開啟都會重新推導 ， 主題、DPI 同密度安全。所有色彩都通過 `StateColor::semantic(MD3::Role::...)` 解析；冇硬編碼亮色模式字面值。每個操作都至少有 44-DIP 目標。每個導引式標記係一個真實、獨立可聚焦推送按鈕，有佢自己嘅可存取名稱同提示；普通 Tab/Shift+Tab 導航同 Enter/Space 啟用係來自同一個喺 Studio 其他地方使用嘅共用按鈕控制。

## 比對語義（`SearchField::textMatches`）

- 空白查詢 → 比對所有野；
- 純文字 → 子字串測試，尊重「大小寫敏感」；「整字」制約比對到 `\b` 風格邊界，而唔使正則表達式解析；
- 正則表達式 → 截止期限強制嘅 Boost.Regex 寬字元搜尋喺 `bambu-regex-worker` 裏，喺大小寫唔敏感時用 `icase`；一個無效、超大、逾時、或無法使用嘅評估**比對全部**（`true`），所以列永遠唔會喺編輯中被消隱。

## 設定

冇野被保留超越每欄位模式切換；模式、旗標同樣本文字係工作階段狀態。`SearchField::GetPattern()` 公開當前模式到主機。原生原始搜尋/模式輸入喺派遣前強制相同 512 碼元單位協議上限。字面值插入係原子化嘅：完全逃逸值只會喺符合剩餘模式預算時插入，所以後設字元擴展唔可以分配或插入超過該上限。

## DeviceWeb 墨水管理員搜尋

嵌入式墨水管理員有佢自己嘅網絡原生實作，因為佢嘅真實搜尋引擎係 JavaScript 而唔係本地 Boost.Regex：

- 工具列搜尋預設保持大小寫唔敏感純文字。其相鄰 44-DIP `.*` 按鈕開啟完整 MD3 構建器；工具列查詢、原始模式、`i m s u` 旗標同模式喺兩個方向同步。本地線軸列已經由原生存放、篩選、搜尋、構建器、分組同活動歷史紀錄保留的本地存放，保持可用，即使喺登出或離線時。新增/編輯/刪除係雲端支援的，而唔係持久排隊離線，所以佢哋同明確雲端拉/推控制需要雲端工作階段。掛載永遠重新整理原生本地預設，但佢唔會力度取得雲端設定或觸發雲端拉，直到橋接確認已認證工作階段。已認證雲端設定要求帶著生存期同生成票證：有效性喺網絡完成時同再次 GUI 線程躍後檢查，VM 銷毀使排隊回呼無效，同新要求推翻任何較舊反應，所以陳舊資料唔可以覆蓋快取。
- 構建器將方言識別為 JavaScript `RegExp`（ECMAScript），解釋斜線/反斜線逃逸，同提供逃逸字面值、字元類別、錨點、擷取/非擷取組、交替同量詞。一個受限樣本編輯器顯示實時範圍、編號同命名擷取，同明確截斷通知。複製只傳回原始模式；JSON 匯出包含方言、模式、模式同旗標，但刻意排除樣本文字。複製/匯出結果使用角落通知堆疊：成功逾時、失敗保持直到解除，同兩者都喺活動歷史紀錄中可檢閱。導引式標記同逃逸字面值喺 256 碼元單位上限原子化：完整插入被應用或模式保持未變，同一個持久警告解釋原因。
- 編譯同比對只會喺可棄置網絡工作者裏發生。每次編輯開始一個新鮮工作者；頁面喺完成、取消、錯誤或 175 毫秒牆面時鐘截止時終止佢。工作者亦都檢查引擎呼叫之間 100 毫秒合作 CPU 預算。冇頁內正則表達式備用。
- 邊界喺結構化複製前同工作者內強制：256 模式碼元單位、8,192 樣本碼元單位、5,000 候選、2,048 碼元單位每候選、1,048,576 聚合候選/識別碼碼元單位、100 預覽比對、20 編號/命名擷取組，同 512 碼元單位每顯示比對或擷取值。零寬度比對喺 `u` 下由 Unicode 碼點推進，否則由一個 UTF-16 碼元單位。
- 待決、無效、超大、逾時、無法使用同崩潰評估開放失敗到已分頁/篩選限制基礎列。呢個阻止一個半鍵入模式或工作者故障從消隱表或清除其當前選擇。
- 構建器係一個無模式、門廊化右側工具介面，唔係決策對話：基礎頁面保持可操作，焦點唔被陷住，Escape 關閉佢，同關閉恢復喚起控制。其單欄窄版面配置避免水準裁剪。分頁使用分頁列表/分頁面板語義同箭頭導航；篩選觸發公開擴展同受控狀態，同佢哋嘅無線電選單支援箭頭、Home/End、Escape、焦點恢復同 44-DIP 目標。工具列分組公開按下狀態；組、雲端、推、歷史紀錄、新增同批次操作亦都符合 44-DIP 目標。英文、香港粵語同衍生雙語模式使用相同翻譯鍵同位檢查。

驗證存活喺 `device_page/tests/filamentRegex.test.ts` 同涵蓋純/正則表達式狀態同步、無效同敵對輸入、硬工作者殺死路徑、Unicode、多行錨點、零寬度推進、擷取同擷取邊界、開放失敗行為、確定土耳其 I 大小寫、原子精確上限插入、離線本地圖書館存取、擁有者銷毀後延遲回呼、不按順序雲端設定反應、變異上限、前複製拒絕、推批次清理，同兩個 ID 候選預取競爭。CMake 嘅 `device_page_build` 同 Windows 預檢都執行該套件加上 DeviceWeb 語言同位，喺構建束之前。佢哋冷凍 pnpm 安裝用 `CI=true` 執行，同構建合約拒絕禁用 TLS 或喺任一個引導程式可執行下載上缺失強制雜湊。

## 安全考慮同邊界

- 模式同樣本文字係**本地評估只有** ， 永遠唔會被傳輸、記錄或保留。
- **模式上限**：512 `wchar_t` 碼元單位（由編輯器、應用程式用戶端、線路解碼器同工作者喺編譯前強制）。
- **主體/樣本上限**：8192 `wchar_t` 碼元單位。構建器樣本編輯器明確截斷同報告該事實；超大程式搜尋候選被拒絕同開放失敗（佢唔會被默默截斷，因此唔可以產生誤導部分字串結果）。
- **比對上限**：前 200 比對被列出/突出顯示。截斷通知只會喺 201 次比對實際存在時出現，唔係只喺結果計數等於上限時。
- **結構上限**：巢狀限制到 32 級；量詞同交替計數同計數重複喺要求離開應用程式前被限制，同被工作者重新檢查。
- **牆面時鐘上限**：每個編譯或比對要求取得 50 毫秒預設（呼叫者可能要求 1、250 毫秒）。應用程式使用框架本地 IPC 到持久幫助程式。喺截止期限逾期時佢終止該處理程序、傳回開放失敗結果，同開始一個新鮮幫助程式下一個安全要求。冇分離正則表達式線程：應用程式啟動喺擁有背景未來預熱被包含幫助程式，同篩選呼叫疊加啟動或另一個 RPC 傳回開放失敗立即，而唔係排隊 UI 線程。處理程序啟動、包含設定同無正則表達式準備就緒 ping 係獨立於評估預算；ping 有兩秒截止同永遠唔回答嘅幫助程式會被殺死。只有喺準備就緒成功之後呼叫者嘅未變 1、250 毫秒編譯/比對截止才開始。啟動失敗報告佢哋嘅精確階段同用受限退避重試。
- **聚合篩選通過上限**：收集篩選為佢哋嘅固定模式同旗標建立一個 `SearchPass`。其候選分享一個截止；第一個逾時、工作者/協定故障、資源拒絕或聚合預算耗盡開啟迴路同所有剩餘候選喺該通過無另一個 IPC 等待開放失敗。聚合截止喺成功模式驗證/準備就緒之後開始，同新篩選通過取得新鮮迴路。
- **記憶體/隔離上限**：Windows 將幫助程式放喺殺死關閉工作物件，帶著 128 MiB 處理程序記憶體上限。Linux 使用 128 MiB 位址空間上限同 8 MiB 堆疊上限。喺 Darwin，當前 XNU 強制 `RLIMIT_AS` 通過佢嘅 Mach VM 地圖大小上限；工作者記錄佢嘅 post-exec 對應基線同安裝硬 `RLIMIT_AS` 同 `RLIMIT_DATA` 上限，最多允許 128 MiB 額外對應，加上 8 MiB 堆疊上限。macOS 父級亦都檢查 `proc_pid_rusage` 物理足跡喺要求活躍時最多每 2 毫秒一次同殺死幫助程式 128 MiB 之上。Windows 使用一個明確繼承句柄列；POSIX post-fork 路徑關閉每個描述符 stderr 之上喺 `exec` 前同明確清除 stdin/stdout 上關閉執行。因此只有預期協定頻道被繼承。幫助程式冇網絡或持久路徑。
- **引擎防禦深度**：工作者上限 Boost.Regex 到 1,000,000 訪問狀態。Boost.Regex 可能提高 `error_complexity`、`error_space` 或 `error_stack`；佢哋映射到穩定太複雜結果。處理程序截止同記憶體上限保持安全邊界，而唔係依賴實作特定例外時序。
- **逾時快取係要求特定**（模式、旗標、操作、主體同比對上限）。敵對樣本唔可以毒害相同模式下一個無害主體。語法同編譯結構故障可能被快取由模式因為佢哋係主體獨立。
- 零寬度比對用 `boost::wsregex_iterator` 語義推進、喺 200 比對上限停止，同永遠唔被描繪為空白突出顯示。
- 生產幫助程式只係喺執行檔旁邊解析。Windows 安裝程式喺 `bambu-studio.exe` 旁邊放 `bambu-regex-worker.exe`；支援非 Darwin POSIX 封裝喺 `bambu-studio` 旁邊安裝 `bambu-regex-worker`。macOS 束縛架構比對幫助程式喺 `BambuStudio.app/Contents/MacOS`；通用構建喺最終束縛簽署前將兩個幫助程式切片合併，就好似主執行檔一樣。

## 失敗模式

- **無效模式** → 紅色友善訊息喺構建器嘅有效性行；欄位本身降級到比對全部，所以主機列表保持填充。
- **病理模式** → 工作者報告佢嘅引擎複雜性守衛或喺牆面時鐘截止時被殺死；構建器報告「模式太複雜無法安全評估」同搜尋降級到無篩選。
- **超大輸入** → 構建器樣本明確截斷帶著通知；超大程式候選開放失敗，無部分評估。
- **缺失/崩潰幫助程式或格式不良 IPC** → 冇進程內備用；搜尋開放失敗同構建器報告正則表達式評估暫時無法使用。稍後要求開始清潔幫助程式。
- **剪貼簿忙碌** → 複製默默跳過（冇資料遺失；模式保持喺編輯器）。

## 驗證

- 登錄列 `no-shared-md3-searchfield`（設計系統同位暫存器）：完成。
- 迴歸涵蓋一定通過構建器通過 `SearchField` 採用者上嘅調整按鈕，確認原始編輯器擁有焦點，之後運動外部點擊同 `Esc` 解除。只測試相鄰 `.*` 切換唔會証明短暫快顯存活啟用。
- 搜尋欄同構建器浮動視圖被擷取每按鈕喺截圖矩陣下 `docs/screenshots/regex-builder/`。
- `bounded_regex_tests` 係一個真實 CTest/CI 目標。佢涵蓋有效、無效同冇比對結果；Unicode 同擷取組；明確多行模式；零寬度推進同比對上限；應用程式同協定邊界；純文字對正則表達式行為；缺失工作者開放失敗處理；同一個敵對巢狀量詞逾時跟著工作者重新啟動/恢復；聚合截止跨越 100 不同敵對候選；精確比對上限語義；非阻擋延遲預熱跟著第一個成功 `SearchPass`，同一個開始工作者永遠唔回答佢嘅 ping；構建器/ImGui 雙向狀態；獨立較低/上限計數重複界限；同 POSIX 描述符隔離、關閉父級 stdio 啟動同有限工作者資源上限。喺 macOS，一個平台特定測試証明被包含工作者對有效、無效、比對同冇比對要求保持功能。CI 亦都用 `SLIC3R_GUI=OFF` 同 `SLIC3R_BUILD_TESTS=ON` 配置測試樹，保持呢個集中引擎安全套件 GUI 目標獨立。Windows 工作流程構建呢個目標同每個推同手動派遣通過 CTest 執行佢。每個 macOS 執行器亦都為其原生架構配置無頭目標同喺應用程式構建後執行相同 CTest 門，所以 Darwin 資源上限同功能路徑喺英特爾同蘋果矽工作上被編譯同運動。
- 視覺/手動涵蓋對焦點、複製、本地化同突出顯示展示保持有用，但佢唔係評估者安全邊界嘅証據；自動化工作者測試係。
