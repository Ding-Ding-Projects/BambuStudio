# 託管顯示縮放可行性探查

`scripts/ci/Probe-HostedDisplayScale.ps1` 係唯讀探索步驟，唔係縮放設定工具，亦唔係已通過嘅矩陣測試。佢只喺可棄置嘅 GitHub 託管 Windows 工作節點執行，並寫入 `RUNNER_TEMP` 之下。準備期間冇喺本機執行。託管執行同私人清單審查仍然待辦。

呼叫工作流程必須先透過其支援嘅託管 UI 路線，喺自己擁有嘅互動工作階段同桌面開啟指定而受支援嘅 Settings 頁面。探查唔會啟動 Settings、改動顯示、選取控制項、登出或者重新啟動任何嘢。佢要求所屬工作階段有一個 `SystemSettings` 處理程序，並喺目前桌面有一個可存取嘅頂層視窗。介面缺失或有歧義時會傳回固定 `unavailable` 原因，唔會估選擇器。

使用 PowerShell 7.4 或更新版本執行：

```powershell
pwsh -NoProfile -File scripts/ci/Probe-HostedDisplayScale.ps1 -OutputDirectory "$env:RUNNER_TEMP/display-scale-probe"
```

父程序預設將隔離 UIA 工作者限時 45 秒（可設定為 5 至 90 秒），之後只終止該自有工作者。最多保留 1,000 筆控制項紀錄。呢個係有界清單，唔係完整性證據。由於並無配置任何縮放，探查一律以 2 結束。只將 `capability.json` 發佈為固定公開摘要。UIA 名稱同 automation ID 留喺 `settings-inventory.json.aesgcm`，以 AES-256-GCM 加密，並用現有 `hosted-automation-public-v1.pem` RSA 接收者配合 OAEP-SHA256。獨立封套記錄 nonce、驗證標籤、已包裝金鑰及密文 SHA-256；唔使用關聯資料。原始提供者文字同例外訊息絕不記錄。封套採用 schema 2 同協定 `display-scale-inventory-v2`，用嚟區分呢份清單、原生執行階段加密協定，以及較早嘅 schema-1 GUI 接收者清單。沿用現有接收者，唔輪換亦唔取代。派送前須確認對應嘅受保護私人託管可用。較早清單會連同原有接收者保留；修改呢個探查唔會令佢哋變得可以解密。使用現有私人接收者託管路線解密及審查清單。現有圖片封存解碼器如冇明確格式轉接器，並唔相容於呢個 JSON 封套。絕不可上傳已解密清單。

### 可選嘅 Colors 目的地探索

探索工作流程只接受固定 `destination` 選項 `display`（預設不變）同 `colors`，分別映射到文件列明嘅 `ms-settings:display` 同 `ms-settings:colors` URI。數值顯示能力探索會喺啟動 Settings 前拒絕 `colors`。探查嘅 `-Destination` 參數只記錄請求意圖，唔可以啟動 URI。唔會點擊、選取、更改 Colors 控制項，亦唔會將佢擷取成圖片。協定啟動係非同步嘅：啟動器完成同初始延遲唔能夠證明已到達指定頁面。兩份公開收據都明確保留 `navigation_completion=unverified`。隱藏啟動只限自有可棄置託管桌面；唔代表協定啟動一定產生不可見頁面。

加密清單而家包含請求目的地、工作流程執行／來源身份、觀察時間、輔助工具雜湊、Settings／根處理程序嘅確切開始時間、工作階段及根控制代碼。來源欄標示為 `workflow_source_commit`，唔係獨立查詢所得嘅簽出身份。呢啲值喺現有 GCM 明文內獲驗證，絕不複製到明文診斷。清單建立前後會重新檢查處理程序／開始時間／工作階段／根身份；外來處理程序控制項或者未完成嘅有界遍歷，都會令結果不可用。支援時只讀取 selection-item 狀態，否則保留未知，方便之後私人辨識真正目的地標記。控制項上限仍為 1,000；標籤上限 2,048 字元；pattern 上限 32 個，每個 256 字元；明文上限 4 MiB。

單靠探索唔會重新整理 Settings，亦唔證明縮放選項曾被快取。唔會根據請求 URI 或缺少 Scale 控制項推斷導航完成條件。執行 `37095094318`，來源 `99ace4b670af24d34c1ba6761b59256ae5e71cb6`，其後產生咗已驗證 Colors 清單，並以預期執行、來源、目的地同探查雜湊開啟。私人審查辨識出下文使用嘅三個頁面專屬控制項。固定 URI 載於 Microsoft [Settings 啟動參考](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings)。

必須先讀獨立而由父程序擁有嘅 `supervisor.json`。佢記錄實際觀察到嘅工作者結束，以及 `teardown_verified`。建立、等待同終止例外只產生固定原因碼，唔含原始診斷。單靠停止請求絕不能證明已終止：父程序會再等最多五秒。如無法觀察到終止，`completed` 同 `inventory_stable` 保持 false，`disposal_required` 為 true，工作者擁有嘅檔案唔可以當作最終證據。父程序絕不覆寫 `capability.json`，避免同仍在執行嘅工作者爭寫收據。呢種情況要透過正常工作生命週期棄置託管機器，唔宣稱成功拆除。缺少 supervisor 收據亦會令全部清單無法獲接納。

## 下一步配置

### 選擇加入嘅已觀察頁面往返

配置工作流程嘅 `refresh_settings_page` 輸入預設為 `false`，只有同時使用 `input_route=hosted-foreground`、`provision_resolution=true` 同 `diagnostic_evidence=true` 先接受；原生產品執行唔可以用呢個選項。量度到受支援嘅 1920×1080 模式後，輔助工具只啟動固定 `ms-settings:colors` URI，觀察該頁，再只啟動 `ms-settings:display` 並觀察返回。唔會點擊 Colors 控制項、擷取 Colors 像素、強制前景啟用，亦唔會將啟動器結束當成導航完成。

Colors 正向判定要求每個已觀察 automation ID 恰好有一個可見且已啟用控制項：

| Automation ID | Type | 必須具備嘅唯讀 patterns |
| --- | --- | --- |
| `SystemSettings_Personalize_Color_ColorMode_ComboBox` | `ControlType.ComboBox` | Selection, ExpandCollapse |
| `SystemSettings_Personalize_Color_AccentColorMode_ComboBox` | `ControlType.ComboBox` | Selection, ExpandCollapse |
| `SystemSettings_Personalize_Color_EnableTransparency_ToggleSwitch` | `ControlType.Button` | Toggle |

兩個目的地都要喺各自十秒區間內取得兩次正向觀察。原有 Settings／根 PID、處理程序開始時間、工作階段、根控制代碼、輸入桌面同顯示身份，全程保持綁定。返回 Display 另外要求唯一 Scale 選擇器，以及已驗證前景同點位擁有權嘅最新幾何。單靠 Runtime-ID 變更或者缺少控制項，唔會獲接受為頁面已重建嘅證據。

導航前會獨佔建立 `navigation.pending`、強制寫入，並綁定持久原始狀態雜湊。只有正向觀察到返回 Display，而且雜湊相同，先可以將佢重新命名為 `navigation.returned`。未解決嘅確認狀態會阻止之後所有縮放輸入同 URI 重試，包括復原，並要求棄置。當子程序終止同原生輸入復原狀態已知，獨立且綁定身份嘅原始解像度復原仍會執行。已停止啟動器或冇處理程序嘅 Job 都唔能夠清除導航不確定性。

來源提交 `5c12f8dd2e6fdbab4de6b134dededec57a6f31ed` 已接受兩次獨立原始碼審查。兩個聚焦案例執行實際標記／範圍判定同持久不確定性，令託管生命週期合約增至十三個案例。喺本文件記錄時，執行 `37095764151`，來源 `3467c83155b4a3881a306eeb5ac9060bdb381ea2`，仍在排隊；十三案例結果同頁面往返仍待完成。呢個係一次改變咗條件嘅診斷假設，唔係快取成因、更高縮放可用性、產品 DPI 或完整矩陣覆蓋嘅證據。

### 一個固定較高模式診斷

配置工作流程而家只接受 `resolution_mode=1920x1080`（預設不變）或 `1600x1200`。後者只限獨立前景執行，而且必須啟用解像度配置、加密診斷同已觀察頁面往返。原生執行會喺啟動前拒絕替代模式；最小尺寸調整請求同轉接器仍然只接受 1920×1080。

唯讀能力執行 `37089435143` 列舉出 1600×1200、每像素 32 位元、64 Hz、方向 0。多出嘅 120 個垂直像素令佢成為不同診斷條件，唔係 200% 縮放可用嘅證據。每次新嘗試都必須重新列舉一個相容固定目標，並保留目前頻率、方向、顯示旗標、位置及受支援公開欄位。現有純測試模式檢查、非持久套用、量度讀回、持久原始位元組，以及獨立縮放／模式還原全部不變。復原會選取已儲存原始模式，絕不選診斷目標。收據喺成功讀回後，先由已驗證模式位元組推導所選尺寸。

只計劃喺 1600×1200 進行一次改變條件嘅 200% 實驗。唔引入任意尺寸、顯示驅動程式更改、登錄更改、自訂縮放或登出路線。聚焦託管合約執行實際固定模式映射同範圍判定，包括拒絕替代原生／最小尺寸執行。託管總數為十四個案例，仍待執行。呢次來源變更同之前四選項選擇器，都唔能夠確立 200% 結果。

私人審查辨識出實際控制項後，另行實作有界 Settings 互動，使用預定義 Scale 選擇器。記錄原有選取同顯示身份，選取每個受支援值，並要求 `GetDpiForWindow` 對 100%、125%、150% 同 200% 分別實際讀到 96、120、144 同 192。亦要記錄目標 DPI awareness：不感知 DPI 嘅視窗無論螢幕縮放幾多都傳回 96。喺 `finally` 還原原有選取並驗證其 DPI。棄置工作者係最後 containment 邊界，唔代表已成功還原。不支援嘅選擇器或值仍然不可用。

唔可以用自訂縮放、登錄替代、偽造 `WM_DPICHANGED` 或 awareness 覆寫，當作已配置螢幕縮放嘅證據。目前原生驅動器會比對要求縮放同實測 DPI，但唔會配置縮放。

Microsoft 有記錄 [Settings 縮放選擇器](https://support.microsoft.com/en-gb/accessibility/windows/make-text-and-apps-bigger)同[動態逐螢幕 DPI 行為](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows)。[GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow) 取決於 awareness。[ChangeDisplaySettingsEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-changedisplaysettingsexa) 記錄嘅係圖形模式更改，唔係螢幕縮放設定器。

## 最小尺寸證據

目前 `GUI_App::get_min_size()` 傳回 `max(1000, 76 * em_unit)` 乘 `max(600, 49 * em_unit)`。`MainFrame` 透過 `SetMinSize` 套用，屬於外框限制。驅動器固定 1000 × 600 實體用戶區矩形係另一個量，唔可以叫做合約最小尺寸。每個語言、主題同 DPI 組合都要量度實際依 em 而定嘅外框最小尺寸及所得用戶區尺寸。驗證要求更細外框時會被限制至該最小尺寸，並檢查所得內容。固定用戶區尺寸可保留為額外可達組合。呢個探查唔改產品最小尺寸或驅動器，亦唔提供版面判定。

### 實測最小尺寸驅動器模式

原生驅動器而家接受 `--viewport measured-minimum`。佢讀取實際主框架現有 layout-probe 嘅 `GetMinSize` 值，將外框調整到該值，並保留實際用戶區尺寸同實測 DPI。唔修改產品限制、唔推斷 em 值，亦唔將固定 1000 × 600 用戶區矩形稱為最小尺寸。每次呼叫及處理程序重啟都會新增一份 `viewport_observations` 收據。

佢亦透過現有 `SetWindowPos` 路線，要求兩個方向都比外框細一個實體像素，記錄所得幾何，喺 `finally` 還原原有實測最小尺寸，再擷取還原後介面。最小尺寸收據引用緊接其後現有 ready 或 restart 主框架擷取，唔新增重複圖片。選單範圍維持恰好 30 張圖片：一個 ready 觀察、五次外層選單互動，以及根選單同巢狀選單檢查各十二次互動。驅動器上限仍為 30，連同 `runtime.json` 同安裝收據，啱好放入包裝器嘅 32 項 manifest。冇移除任何逐輸入圖片。只有精確返回實測最小尺寸先獲得 `observed_programmatic_clamp`。原生互動最小尺寸追蹤同程式化調整唔等同：如果程式化請求冇被限制，診斷記錄 `not_observed`，但唔會令量度正確嘅最小尺寸組合失敗。互動驗證仍待辦。即使有程式化限制，`interactive_resize_clamp` 仍明確係 `unverified`；呢個唔證明滑鼠拖邊或鍵盤調整。唔可以放寬產品最小尺寸去令探查通過。

喺已配置嘅託管 Windows 工作上，完成已安裝成品驗證後：

```powershell
python scripts/md3/drive-native-interface.py --exe $exe --cli $cli --install-receipt $receipt --source-commit $commit --release-tag $tag --output $output --scope slice-controls --viewport measured-minimum --language en --theme light --scale 1.0
```

只喺真正配置好嘅 DPI，以及獨立要求嘅語言同主題組合重複。呢次來源變更冇喺本機執行。託管結果、加密像素審查同互動限制證據仍待辦。

### 專用互動最小尺寸範圍，託管驗證待辦

選擇加入嘅 `minimum-resize` 範圍要求 100% 縮放嘅 `measured-minimum`。呢條基準路線有託管證據之前，仍排除較高縮放。驗證器將完整驅動器程序樹放入具名而不可脫離嘅 Job，限時 900 秒。現有範圍維持只用隱藏路線。

呢個範圍明確透過官方已安裝 MCP 1.x 用戶端（最少 1.2.0），使用固定後端嘅相容 MCP stdio 伺服器。呢個唔係 cheap CLI 嘅持久模式。同一伺服器跨 show/hide 保留原始 Default 輸入桌面控制代碼同安全橫幅。真正指標拖曳經現有 cheap CLI，喺自有桌面嘅現有工作者執行。唔使用直接設定尺寸命令或偽造 nonclient 輸入訊息。

輸入前，觀察器要求相同處理程序／開始身份、HWND、執行緒／輸入桌面、前景框架、DPI、無遮擋指標路徑，以及由有界唯讀命中測試取得最新 `HTBOTTOMRIGHT` 結果。框架開始時，闊高都必須恰好比實測外框最小尺寸大 80 像素，而且唔可以最大化。一次對角拖曳嘅目標係比最小尺寸細 40 像素。成功要求確實縮細、左上位置同最小尺寸不變、最終外框尺寸精確、96 DPI，以及觀察到滑鼠按鈕已放開。前後圖片保持加密，必須獨立審查像素。呢個隔離範圍只喺 ready 圖片之外加兩張圖片，選單範圍嘅擷取配額不變。

持久伺服器關閉之前會還原原始框架同輸入桌面，並檢查伺服器結束。如按鈕放開狀態未知，就阻止還原輸入同桌面切換；呼叫失敗並要求棄置主機。完整 Job 終止絕唔代替輸入放開或桌面還原證據。呢份來源實作未曾喺本機或託管環境執行。

## 有界預定義縮放配置

`scripts/ci/Invoke-HostedDisplayScale.ps1` 係另一個只限託管嘅輔助工具。獨立使用時要求 Display Settings 已開啟，並使用現有固定版本 `lowlevel-computer-use-cheap` 可執行檔。UI Automation 只讀取已觀察到嘅 `SystemSettings_Display_Scaling_ItemSizeOverride_ComboBox`、其選取值同受支援預定義項目。預設輸入使用以 HWND 為目標嘅 cheap 滑鼠點擊，之前會即時檢查處理程序、工作階段、桌面、啟用狀態同幾何。目標缺失或有歧義會產生不可用結果，唔會嘗試猜測性輸入。

```powershell
& scripts/ci/Invoke-HostedDisplayScale.ps1 -ScalePercent 125 -OutputDirectory "$env:RUNNER_TEMP/scale-125" -CheapExecutable $env:LLCU_CHEAP
```

允許百分比為 100、125、150 同 200。輔助工具喺輸入前儲存已觀察原始選取，要求所選值同現有 Settings 框架上嘅 `GetDpiForWindow` 同時符合請求，並喺 `finally` 還原原始選取同 DPI。另一個有界復原工作者會喺第一個工作者終止後檢查還原。終止或還原未驗證時必須棄置託管 runner，絕唔係成功結果。輔助工具執行緒只為座標轉換使用逐螢幕 awareness；呢個唔會配置縮放，亦絕唔獲接納為縮放證據。

預設輔助工具支援獨立控制項量度，冇通用動作腳本參數。下文明確嘅原生執行階段整合，只會喺目前呼叫驗證咗請求選取同 Settings DPI 後，使用固定已安裝產品驅動器。獨立量度唔證明產品視窗 DPI、像素、版面或擷取審查。

每個輔助處理程序都以暫停狀態啟動，喺第一條指令前加入不可脫離嘅 Windows Job。活動處理程序數為零先證明整棵自有程序樹已終止；直接處理程序結束並不足夠。每次建立前先持久寫入 pending 標記，只有取得上述證明先重新命名。任何殘留 pending 標記都阻止進一步輸入、還原及復原，並要求棄置 runner。Job 採用關閉即終止語意作為 containment 後備，唔代替終止判定。一般工作者輸出同全部標準錯誤都送往 NUL。只擷取 cheap JSON 輸出，上限 64 KiB，並有有界程序時限及最後一秒排空。唔保留無界串流讀取或通用子動作輸出。管道讀取器獨佔 `SafeFileHandle`，直至其工作完成，包括有界排空傳回不可用時。程序拆除絕不喺排隊或活動讀取下面關閉原始管道控制代碼。延伸啟動屬性將繼承限制於指定標準串流控制代碼。

只有 `supervisor.json`、`run.json` 同 `restore.json` 係可安全公開收據。絕不上傳 `original.json`：佢係私人復原狀態，包含處理程序同工作階段身份。內部 `child-*.pending*` 生命週期標記亦排除發佈。輔助工具唔轉送原始子程序輸出或 UI 標籤。來源語法剖析唔等同託管執行；選取、原生 DPI 同還原收據通過獨立審查之前，獨立配置仍未驗證。

選取診斷保留固定失敗階段名稱，獨立於還原失敗階段名稱。輸入後，輔助工具最多三秒唯讀觀察 combo 嘅 `ExpandCollapsePattern`，而且必須確認展開先解析選項。固定純量觀察記錄輸入目標類別、cheap 結束同終止判定、展開狀態，以及符合選項數。成功還原唔可以代替呢啲觀察。收據區分輸入確認同已觀察轉換；唔會確立已張貼滑鼠訊息改動咗 Display Settings。

明確 `-InputRoute hosted-foreground` 選項則喺完全可棄置嘅 GitHub 託管 Windows 機器，使用現有 cheap 絕對座標滑鼠輸入。本機或私人桌面不可用。佢要求實際輸入桌面同輔助執行緒都係 `WinSta0\Default`，Settings 已擁有前景根，而且目標點解析到相同自有根同處理程序。輸入前重新檢查即時程序開始身份同最新已啟用 UIA 幾何；輸入後再檢查前景同點位擁有權。唔會自動啟用任何視窗。展開、所選值／DPI 觀察仍屬必須，還原亦重複相同擁有權檢查。子程序終止不確定仍然禁止還原。

呢條前景路線刻意承認非原子性：最後檢查同獨立 cheap CLI 輸入之間，仍可能有其他前景變更。限制呢個風險嘅係完整可棄置主機範圍，唔係原子 HWND 保證。收據明確記錄路線，並將 `foreground_input_atomic` 設為 false。桌面改變、點位被遮擋、缺少前景擁有權或未觀察到語意轉換，都產生不可用證據，絕非成功。

輸入後擁有權採用唯一 Scale combo 目前實體矩形嘅最新觀察，保留原有 Settings 程序身份同自有根。三秒有界唯讀收斂容許 DPI 變更後合理版面移動；絕不重用已選選項過時點位或發出另一個輸入。展開選項診斷只公開預定義 100/125/150/200 範圍內嘅計數：已觀察、可見且啟用、符合選取容器，以及容器觀察不可用。零計數唔證明某縮放不支援；虛擬化同顯示限制仍需各自證據。

## 選擇加入嘅原生執行階段整合，驗證待辦

`run-scaled-native-interface.py` 係現有原生驅動器嘅固定轉接器。其有界請求拒絕未知同重複欄位，包含預定義選項及雜湊，唔包含可執行檔或腳本路徑。全部路徑由目前託管呼叫推導，並拒絕 reparse points。轉接器保留驅動器實際視窗 DPI 檢查，以及自有程序同桌面拆除。佢亦會針對確切具名 Job，查詢實際 holder 同產品 PID，包括重啟後接管嘅產品 PID。

可選 `HostedScaleProcess.RunNamed` 入口建立全新隨機 256 位元 Job 名稱，並設只查詢 SID 及 OWNER RIGHTS 項目。現有匿名入口不變。查詢控制代碼只短暫存在，並喺 `finally` 關閉；明確終止同零活動程序證明仍屬必須。呢個存取限制唔係對抗同一使用者或特權程式碼嘅沙箱。託管生命週期腳本而家有六個有界案例，包括真正正向成員查詢，以及負向指派、終止、設定同擁有者安全存取嘗試。準備好來源唔代表新增檢查已通過。喺配置縮放下執行產品同像素審查，要等確切託管候選提供結果先算驗證。

`Verify-HostedNativeInterface.ps1 -ProvisionDisplayScale` 可選擇加入 125%、150% 或 200%；現有 100% 路線不變，並拒絕該開關。安裝、套件摘要驗證同固定工具啟動準備，必須喺縮放改動前完成。驗證器喺 `RUNNER_TEMP` 建立全新、有界、綁定雜湊嘅請求。受限制嘅純驗證轉接器階段喺 Settings 輸入前檢查請求，之後 supervisor 喺啟動受限制縮放工作者之前，立即以隱藏啟動設定開啟固定 `ms-settings:display` URI。唔支援任意 URI 或強制前景啟用。工作者仍要求觀察到 Settings 身份同前景擁有權。獨立工作繼續自行開啟 Settings 介面。固定轉接器喺啟動產品前再次驗證請求。冇請求欄位可以選擇任意可執行檔、腳本或檔案系統位置。

縮放工作者只有觀察到指定選取，並量度到預期 Settings 視窗 DPI 後，先呼叫轉接器。轉接器具名而不可脫離嘅 Job 限時 1,800 秒；外層匿名縮放工作者 Job 容許 1,920 秒，之後另有有界 60 秒復原。請求驗證容許 20 秒。外層工作流程時限必須超過以上限制，加上安裝、工具準備、終止寬限期同加密時間。逾時一律失敗，即使較早 runtime 收據寫成功亦一樣。

原生接納要求轉接器結束碼為零、完整程序樹終止已驗證、最新請求同 runtime 雜湊、精確來源／版本／執行／範圍／組合綁定、實際 holder 同產品成員資格、原生驅動器逐視窗 DPI 同自有程序／桌面拆除檢查，以及獨立還原成功。現有加密步驟執行前，還原必須完成。如果 containment 不確定，驗證器唔讀取或加密證據，記錄必須棄置，亦絕不接納殘留 runtime 收據。即使加密成功，像素仍待獨立審查。請求、轉接器收據、隨機 Job 名稱同內部生命週期檔案保持私人，絕不上傳。

指定實作嘅獨立生命週期同獨立配置檢查通過前，唔好派送產品縮放矩陣。存在選擇加入接口唔等於已完成縮放矩陣判定。

## 唯讀託管顯示能力觀察

`Probe-HostedDisplayCapabilities.ps1 -OutputDirectory <new RUNNER_TEMP child>` 要求可棄置託管 Windows 機器已開啟 Display Settings。匿名不可脫離 Job 將其唯讀工作者限制於 45 秒，並沿用現有有界終止證明。只上傳 `receipt.json`。

工作者將唯一已觀察 Settings Scale 根綁定到實際螢幕，讀取目前顯示模式，並用 `EnumDisplaySettings` 列舉最多 512 個受支援模式。佢亦觀察唯一 Settings 解像度 combo，要求所選數值尺寸同目前模式一致。接納前再次檢查程序開始身份、螢幕身份同目前模式。觀察前後，`QueryDisplayConfig(QDC_ONLY_ACTIVE_PATHS)` 都必須證明恰好一個活動顯示目標。多個目標，包括複製目標，保持不可用，唔會假設 Settings 選咗承載自己視窗嘅螢幕。解像度候選必須屬於完全相同已觀察 Scale 根。顯示路徑身份保持私人。每個模式附上數值 `fields` 遮罩；除非設有 `DM_DISPLAYORIENTATION`，否則方向為 null，穩定性檢查會區分缺少方向同量度到零。公開收據只包含固定狀態值、數值尺寸、位元深度、更新頻率、方向、計數同主螢幕旗標。絕不輸出裝置名稱、程序／視窗身份、UI 標籤或原始例外。

呢個診斷唔發送輸入、唔展開控制項、唔改解像度或縮放，亦唔寫登錄設定。較大受支援解像度只係日後有界調查嘅證據，唔證明有提供 150% 或 200% 縮放。解像度觀察缺失或有歧義、模式列舉未完成，都保持不可用。任何未來解像度更改都需要自己嘅受支援輸入、精確原始狀態保留，以及已驗證解像度加縮放還原。

## 固定較大解像度區間

縮放輔助工具明確 `-ProvisionResolution` 選項要求 `-InputRoute hosted-foreground`。佢唯一原生執行階段組合係下文嘅基準最小尺寸組合；其他組合喺輸入前拒絕。佢只要求以目前更新頻率及已觀察方向，重新列舉嘅 1920×1080、32 位元模式。不支援或有歧義嘅變體保持不可用。唔接受任意尺寸或動作接口。

喺 `CDS_TEST` 或模式變更前，工作者以原子方式保留原有縮放／DPI、完整已驗證 220 位元組 `DEVMODEW`，以及私人裝置同單一活動來源／目標身份。非零 `dmDriverExtra`、未知顯示欄位位元或不支援結構尺寸會被拒絕，唔會靜靜丟棄欄位。目標保留有效位置、方向、顯示旗標同固定輸出語意。`ChangeDisplaySettingsEx` 先用 `CDS_TEST`，再用旗標零作動態非持久變更。絕不使用 null 模式、登錄持久化、自訂縮放、重新啟動或登出。

嘗試後會重新讀取目前模式，包括傳回非零嘅情況。每個文件列明而有效嘅請求欄位都必須一致；填補位元組同未指定方向唔當成觀察。工作者喺嘗試指定預定義縮放前，記錄解像度造成嘅任何自動縮放／DPI 變更。模式變更同縮放輸入前，會重新檢查活動顯示身份。

還原會獨立嘗試原有縮放同精確原有模式，所以 UIA 失敗唔可以跳過安全而綁定身份嘅模式還原。最終接納要求原有模式，加上最新原有縮放／DPI 觀察。復原先檢查目前模式，喺還原部分完成後仍具冪等性；模式還原先於 UIA 初始化執行，令 Settings 缺失唔會阻止嗰次嘗試。子程序終止未知、顯示身份改變，或者原生輸入復原不確定，都會阻止改動並要求棄置。完整工作者程序樹終止後，獨立解像度工作者容許 180 秒，獨立復原容許 90 秒。現有純縮放同產品轉接器時限不變。

公開收據只新增固定數值尺寸、原生傳回碼同驗證布林值。精確模式位元組及裝置／路徑身份留喺私人 `original.json`，排除上傳。已驗證較大解像度本身唔證明提供 150% 或 200%；現有縮放探查仍要觀察選項、所選值、實際 Settings DPI 同還原。

執行 `37090148387` 喺 `capture_original_resolution` 停止，尚未配置模式或縮放。呢個粗略階段唔指出邊個原生觀察不可用。輔助工具而家用固定階段名稱同數值 API 傳回碼，分別記錄選取及還原原生診斷。佢哋區分拓撲、來源裝置結構及查找、已連接主裝置驗證、螢幕綁定同模式驗證。來源裝置名稱結構喺 API 呼叫前必須量度為恰好 84 位元組。診斷唔包含例外文字、裝置名稱、控制代碼或私人復原位元組。要等有界託管觀察提供更細階段，先可以驗證成因。

執行 `37090623816` 將不可用擷取收窄到 `mode_size_and_driver_extra`。下一個診斷只記錄最後檢查嘅緩衝區長度，同數值 `dmSize`／`dmDriverExtra` 欄位。Null 表示冇檢查過足夠大嘅結構；如果復原喺再次讀模式前失敗，呢啲值可能描述較早選取。原有 220 位元組、零額外資料接納合約不變。`EnumDisplaySettingsW` 收到已初始化 `dmSize` 同零額外容量；文件所述驅動額外容量合約，唔構成接納或還原截斷私人資料嘅理由。最後 enum-success 布林值亦區分讀取失敗：之前 null 結果傳入共用驗證器，會以尺寸／額外資料階段覆蓋 enum 階段。Null 而家有自己嘅 `mode_read_returned_null` 階段。所以較早階段唔能確立任何傳回標頭欄位無效。執行 `37091086128` 其後量度到列舉成功、220 位元組緩衝區、傳回 `dmSize=188` 同 `dmDriverExtra=0`。輔助工具而家只接受完整 220 位元組配置內已知 188 位元組同 220 位元組公開版面。每個獲接受顯示欄位都喺第 188 位元組或之前結束。實際傳回 `dmSize` 同全部緩衝區位元組都保留供復原，並原封不動傳回；輔助工具絕不將標頭提升為 220，亦唔清除私人資料容量。未知尺寸、非零額外資料、未知有效欄位位元及缺少必須欄位，仍會拒絕。原生身份、測試／套用同還原檢查不變。

現有託管生命週期腳本執行實際輔助工具驗證：五個不支援標頭／欄位案例必須先失敗，之後兩個已知版面先通過；成功檢查必須保留完整位元組同傳回尺寸。呢個案例唔呼叫原生顯示 API。託管合約結果同實際模式套用／還原仍待辦；冇喺本機執行。

### 固定解像度基準最小尺寸證明

獨立解像度執行 `37091384649` 通過七個生命週期案例，並觀察到 1920 × 1080、125%、Settings DPI 120。佢還原原有 1024 × 768 模式同 100%／96 DPI，兩棵工作者程序樹都已終止，而且唔需要棄置。呢啲證據唔證明產品互動最小尺寸。

`Verify-HostedNativeInterface.ps1 -ProvisionResolution` 而家選擇一個有界組合：`minimum-resize`、`measured-minimum` 同縮放 `1`。將該開關同縮放配置或其他範圍並用會被拒絕。安裝及套件／雜湊驗證喺顯示改動前完成。固定請求除咗現有套件、可執行檔、驅動器及 containment 身份，亦綁定 1920 × 1080 選項、顯示模式同最小尺寸輔助工具來源雜湊。轉接器將自己確切具名 Job 傳畀最小尺寸輔助工具。Settings 必須先報告 100% 同 DPI 96；產品現有獨立 DPI 同真正拖曳檢查仍屬必須。原生工作者保留 1920 秒外層限制、1800 秒轉接器限制，以及獨立 90 秒顯示復原限制。

啟動產品前，工作者持久建立包含請求摘要嘅 `native-input.started`。只有固定轉接器可以發佈相符 `native-input.restored` 收據，而且必須先通過確切最小尺寸操作、按鈕放開、框架還原、原始輸入桌面還原、伺服器結束同原生拆除證據。最小尺寸輔助工具喺持久伺服器結束後，會喺 `Default` 再觀察按鈕放開。呢啲私人檔案唔屬於公開上傳或加密產品證據清單。started 標記絕不移除，Job 達零程序亦唔能提供還原證據。

轉接器被中斷、還原收據缺失或不符，或者按鈕／桌面狀態不確定，都會喺模式變更或 Settings 輸入前，阻止工作者還原同獨立復原工作者。固定 supervisor 收據報告 `input_recovery_uncertain`，並要求棄置。即使中斷發生喺第一次拖曳之前，亦刻意採取保守處理。輸入復原成功先容許現有原有縮放同原有模式還原；最終接納仍要求完整程序樹終止同全部原始顯示觀察。唔引入強制焦點、合成調整尺寸訊息或模擬 DPI。組合 runtime 同真正擷取證據仍待託管驗證；冇喺本機執行。

### 加密較高縮放能力診斷

`Invoke-HostedDisplayScale.ps1 -DiagnosticEvidence` 係獨立 `hosted-foreground` 探索嘅明確選擇加入功能。同 `NativeRuntime` 並用會被拒絕，亦唔傳畀復原。佢唔啟用另一條輸入路線、焦點啟用、捲動、登錄更改或不支援縮放選取。
