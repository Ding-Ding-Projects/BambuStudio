# LAN 模型投遞

同一個區域網絡上嘅人，可以用手機或者手提電腦嘅瀏覽器，將 3D 模型傳去呢部電腦嘅 Bambu Studio。一個細網站喺
Docker 容器入面運行（即係呢個儲存庫 `lan-model-drop/` 資料夾入面嘅 `lan-model-drop` 服務）；Bambu Studio
係負責收件嘅接收站。每個模型都會等你處理：你揀「開啟」之前，乜都唔會開啟、切片或者打印。

呢個選項預設關閉。

## 喺邊度搵到

- **偏好設定，LAN 模型投遞。** 偏好設定分頁列入面獨立一節，排喺「其他」後面。入面有開關**接收 LAN
  投遞網站傳嚟嘅模型**、邀請，同埋連接相關嘅幾行。
- **檔案，LAN 模型投遞...** 會打開嗰一節，停喺開關度。
- **檔案，邀請人傳送模型...** 會打開邀請對話框。
- **指令面板（Ctrl+Shift+F）。** 「邀請人傳送模型」、「LAN 模型投遞設定」同埋嗰一節每一行（「接收 LAN
  投遞網站傳嚟嘅模型」、「邀請連結同 QR 碼」、「測試連接」、「投遞網站地址」、「接收站金鑰」、「投遞碼」）
  都會直接跳去嗰一行。
- 偏好設定入面嘅**設定搜尋**都搵到同樣嘅幾行。
- **標題列。** 選項開咗嘅時候，通知鈴左邊會有個 LAN 指示燈。連接到就係主色，有問題就係錯誤色，連接緊就係
  中性色；收到但未處理嘅檔案數目會顯示喺角標，撳落去會打開邀請對話框。佢嘅提示文字就係佢嘅無障礙名稱，
  會講出狀態。

## 設定步驟

1. 喺網絡上一部電腦（通常就係呢部）照佢嘅 README 開投遞網站，例如喺 `lan-model-drop/` 入面行
   `docker compose up -d`。預設會開放 8833 埠。
2. 喺嗰部電腦讀接收站金鑰：
   `docker compose exec lan-model-drop node server/station-key.mjs`。
3. 喺 Bambu Studio 打開**檔案，LAN 模型投遞...**，打開**接收 LAN 投遞網站傳嚟嘅模型**，將金鑰貼入
   **接收站金鑰**，再撳**儲存金鑰**（或者 Enter）。
4. 容器喺呢部電腦運行嘅話，**投遞網站地址**保留 `http://localhost:8833` 就得；否則就填 Bambu Studio
   連去嘅地址，例如 `http://my-nas.local:8833`。呢格接受 `http://` 或者 `https://`、主機名稱或者
   IPv4 地址，同埋可有可無嘅連接埠；其他寫法會被拒絕並解釋原因，唔會儲存。
5. **測試連接**會先檢查 `/healthz`，再用金鑰查接收站狀態。狀態行會顯示已連接（連埋接收站名稱）、連唔到、
   接收站金鑰唔啱、唔支援呢個協定、需要接收站金鑰、地址無效，或者受保護嘅金鑰儲存用唔到。

## 邀請

邀請就係你交畀傳送模型嗰個人嘅嘢。佢喺偏好設定嗰一節嘅開關正下面，所以選項一開咗，佢就係第一樣見到嘅
嘢；亦都喺**邀請人傳送模型**對話框入面：選項未開嘅時候，對話框會提供**開啟 LAN 模型投遞**，開咗之後
連結一出現，焦點就會移去**複製連結**。

- **連結**係 `<base>/#code=<投遞碼>`，以可以選取嘅文字顯示。投遞碼放喺 # 後面，所以唔會入伺服器記錄，
  亦唔會喺 Referer 標頭出現；網站會讀出佢、填好投遞碼欄，再喺網址列移除 # 後面嗰段。
- **連結開頭**按呢個次序揀：容器有報公開網址就用佢（`DROP_PUBLIC_URL` 提供嘅 `publicUrl`，用喺反向代理
  或者固定名稱）；否則用設定嘅地址，只要佢唔係本機迴路地址；再唔係就用
  `http://<呢部電腦嘅私人區域網絡 IPv4>:<連接埠>`，協定同連接埠跟設定。呢部電腦有幾個私人 IPv4 地址
  （10/8、172.16/12、192.168/16）嘅話，可以喺**呢部電腦嘅地址**揀一個，會記住你嘅選擇。永遠唔會提供
  迴路、鏈路本地、多播或者公開地址。連結下面有一行講明用緊邊個開頭。冇得用嘅開頭時，邀請會解釋原因，
  唔會顯示連結。
- 連結下面亦都會分開顯示開頭同投遞碼（「或者打開 ...，再輸入投遞碼 ...」），方便自己打字、唔掃碼亦唔撳連結
  嘅人。
- **複製連結**會將嗰條連結原封不動放入剪貼簿，並向螢幕閱讀器宣佈「連結已經複製到剪貼簿。」
- **QR 碼**用內置編碼器（同本機安全配對用嗰個一樣）編碼同一條連結，深淺色主題都係白底黑碼，四格靜區。
  佢嘅無障礙名稱係「邀請連結嘅 QR 碼」。**放大 QR 碼**，或者撳一下個碼，會打開大圖，方便手機喺遠啲
  掃描。
- **新連結**會叫容器整一個新投遞碼（`POST /api/station/drop-code`），用舊投遞碼嘅連結就會失效。
  `DROP_CODE` 固定咗投遞碼嘅話，呢個掣會停用，邀請會解釋點樣喺投遞網站改。
- Bambu Studio 由接收站狀態攞到目前嘅投遞碼之後，連結先會出現；喺嗰之前，邀請會講明佢等緊乜。

**投遞碼**一行會顯示同一個碼，旁邊有**新投遞碼**掣。

## 收到模型嘅時候

選項開咗嘅時候，Bambu Studio 每 5 秒檢查一次投遞網站。出錯之後會等 10、20、40，然後 60 秒先再試；
再次連到網站就會返去每 5 秒。

每個新檔案都會先下載，再檢查大小同網站列出嘅一樣、SHA-256 摘要同列出嘅一樣（有 `X-Content-SHA256`
標頭嘅話都要一樣），同埋檔名保留咗一個接受嘅副檔名，而且同列出嘅類型同內容吻合（3MF、STL、STEP、OBJ、
AMF）。檔案會儲存喺資料資料夾嘅 `lan-model-drop/received/<id>/<檔名>`；檔名會先簡化做安全嘅基本名稱。

之後會彈出通知「<寄件人> 傳咗 <檔案>（<大小>）」，或者「有人傳咗 <檔案>（<大小>）」，有兩條連結：

- **開啟**會行同拖放檔案入視窗一樣嘅載入流程，所以未儲存項目、或者將 3MF 當項目開嘅問題照樣會問。
  之後 Bambu Studio 會叫投遞網站刪除佢嗰份。
- **捨棄**會移除本機嗰份，再叫投遞網站刪除佢嗰份。

關閉通知，檔案會繼續等。邀請會顯示幾多個檔案等緊處理，**顯示出嚟**會再彈出佢哋嘅通知。檢查唔過嘅檔案會
被拒絕，並有警告講明原因，同時會喺投遞網站刪除。試咗三次都下載唔到嘅檔案會留喺投遞網站直到過期；將選項
關咗再開就會再試。從未開啟過嘅檔案，下次啟動時會喺資料資料夾移除，投遞網站仲有嘅話會再收到一次。開啟過嘅
檔案會保留佢個資料夾，因為項目可能指住佢；想將項目放去第二度，請用「另存項目」。

## 安全同私隱

- 接收站金鑰係秘密。佢只會以目前 Windows 帳戶嘅 DPAPI 加密資料儲存（`CryptProtectData`，有用途熵，
  禁止使用者介面），放喺資料資料夾嘅 `lan-model-drop/station-key.dpapi`，永遠唔會寫入設定檔。第二個
  帳戶，或者喺第二部電腦嘅資料夾副本，都解唔開；所以完整備份資料資料夾時，只會帶走嗰份加密資料，永遠唔會
  帶走明文金鑰。其他系統會報告儲存用唔到，而唔會用純文字保存金鑰。
- 金鑰永遠唔會寫入記錄。請求只會帶 `Authorization: Bearer <金鑰>` 同 `Accept`：程式平時嘅額外標頭會
  被移除，唔會跟隨重新導向，傳輸追蹤亦都關閉。記憶體入面嘅金鑰副本用完會被覆寫。遮蔽咗嘅欄位可以用眼睛掣
  顯示；兩個欄位都唔會被擷取、記入歷史或者匯出。
- 所有網絡工作都喺一條背景執行緒做。結果只會經事件佇列、而且只喺主視窗仲存在嘅時候先到達視窗。關閉程式時，
  背景執行緒會喺視窗拆走之前停低：設定取消旗標、中止進行中嘅傳輸、喚醒執行緒再等佢完結。
- 唔會自動開啟、切片或者打印。冇任何分析或者遙測。

## 設定

| 鍵 | 意思 |
| --- | --- |
| `lan_drop_enabled` | 開關；唔係 `true` 就係關閉 |
| `lan_drop_address` | 投遞網站地址，預設 `http://localhost:8833` |
| `lan_drop_invite_ipv4` | 邀請連結揀用嘅私人區域網絡地址 |

## 驗證

- `node --test tests/lan_model_drop/model_native.test.mjs` 會用 `g++ -std=c++17 -Wall -Wextra -Werror`
  將 `tests/lan_model_drop/lan_model_drop_model_test.cpp` 同唔用 wx 嘅純邏輯一齊編譯再執行：協定解析同
  驗證、接受嘅類型同內容、檔名同寄件人名稱、退避時間表、狀態分類、地址、邀請連結開頭同連結，同埋收件匣
  追蹤。
- `node --test tests/lan_model_drop/app_wiring.test.mjs` 會讀原始碼，檢查獨立嘅設定一節、選單項目、
  指令面板條目、指示燈、DPAPI 儲存、金鑰唔會寫入記錄或者設定、每個請求都喺背景執行緒做並經事件佇列到達
  視窗、關閉次序，同埋唔會自動開啟。每條規則亦都會對改動過嘅原始碼再行一次，證明佢真係會失敗。
- 接收站原始碼喺 Linux 語法檢查編譯得到；只限 Windows 嘅部分（DPAPI、網絡介面列舉、無障礙事件）只係
  人手審閱過。未試過喺真正網絡上，用已建置嘅 Windows 程式連接真正嘅投遞網站。
