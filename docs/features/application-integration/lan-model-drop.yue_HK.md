# LAN 模型投遞

同一個區域網絡上嘅人，可以用手機或者手提電腦嘅瀏覽器，將 3D 模型傳去呢部電腦嘅 Bambu Studio。一個細網站喺
Docker 容器入面運行（即係呢個儲存庫 `lan-model-drop/` 資料夾入面嘅 `lan-model-drop` 服務）；Bambu Studio
係負責收件嘅接收站。每個模型都會等你處理：你揀「開啟」之前，乜都唔會開啟、切片或者打印。

呢個選項預設關閉。

## 喺邊度搵到

- **偏好設定，LAN 模型投遞。** 偏好設定分頁列入面獨立一節，排喺「其他」後面。入面有開關**接收 LAN
  投遞網站傳嚟嘅模型**、邀請，同埋連接相關嘅幾行。
- **檔案，LAN 模型投遞...** 會打開嗰一節，停喺開關度。
- **檔案，邀請人傳送模型...** 會打開邀請對話框。
- **指令面板（Ctrl+Shift+F）。** 「邀請人傳送模型」、「LAN 模型投遞設定」同埋嗰一節每一行（「接收 LAN
  投遞網站傳嚟嘅模型」、「邀請連結同 QR 碼」、「測試連接」、「投遞網站地址」、「接收站金鑰」、「投遞碼」）
  都會直接跳去嗰一行。
- 偏好設定入面嘅**設定搜尋**都搵到同樣嘅幾行。
- **標題列。** 選項開咗嘅時候，通知鈴左邊會有個 LAN 指示燈。連接到就係主色，有問題就係錯誤色，連接緊就係
  中性色；收到但未處理嘅檔案數目會顯示喺角標，撳落去會打開邀請對話框。佢嘅提示文字就係佢嘅無障礙名稱，
  會講出狀態。

## 設定步驟

1. 喺網絡上一部電腦（通常就係呢部）照佢嘅 README 開投遞網站，例如喺 `lan-model-drop/` 入面行
   `docker compose up -d`。預設會開放 8833 埠。
2. 喺嗰部電腦讀接收站金鑰：
   `docker compose exec lan-model-drop node server/station-key.mjs`。
3. 喺 Bambu Studio 打開**檔案，LAN 模型投遞...**，打開**接收 LAN 投遞網站傳嚟嘅模型**，將金鑰貼入
   **接收站金鑰**，再撳**儲存金鑰**（或者 Enter）。
4. 容器喺呢部電腦運行嘅話，**投遞網站地址**保留 `http://localhost:8833` 就得；否則就填 Bambu Studio
   連去嘅地址，例如 `http://my-nas.local:8833`。呢格接受 `http://` 或者 `https://`、主機名稱或者
   IPv4 地址，同埋可有可無嘅連接埠；其他寫法會被拒絕並解釋原因，唔會儲存。
5. **測試連接**會先檢查 `/healthz`，再用金鑰查接收站狀態。狀態行會顯示已連接（連埋接收站名稱）、連唔到、
   接收站金鑰唔啱、唔支援呢個協定、需要接收站金鑰、地址無效，或者受保護嘅金鑰儲存用唔到。

## 邀請

邀請就係你交畀傳送模型嗰個人嘅嘢。佢喺偏好設定嗰一節嘅開關正下面，所以選項一開咗，佢就係第一樣見到嘅
嘢；亦都喺**邀請人傳送模型**對話框入面：選項未開嘅時候，對話框會提供**開啟 LAN 模型投遞**，開咗之後
連結一出現，焦點就會移去**複製連結**。

- **連結**係 `<base>/#code=<投遞碼>`，以可以選取嘅文字顯示。投遞碼放喺 # 後面，所以唔會入伺服器記錄，
  亦唔會喺 Referer 標頭出現；網站會讀出佢、填好投遞碼欄，再喺網址列移除 # 後面嗰段。
- **連結開頭**按呢個次序揀：容器有報公開網址就用佢（`DROP_PUBLIC_URL` 提供嘅 `publicUrl`，用喺反向代理
  或者固定名稱）；否則用設定嘅地址，只要佢唔係本機迴路地址；再唔係就用
  `http://<呢部電腦嘅私人區域網絡 IPv4>:<連接埠>`，協定同連接埠跟設定。呢部電腦有幾個私人 IPv4 地址
  （10/8、172.16/12、192.168/16）嘅話，可以喺**呢部電腦嘅地址**揀一個，會記住你嘅選擇。永遠唔會提供
  迴路、鏈路本地、多播或者公開地址。連結下面有一行講明用緊邊個開頭。冇得用嘅開頭時，邀請會解釋原因，
  唔會顯示連結。
- 連結下面亦都會分開顯示開頭同投遞碼（「或者打開 ...，再輸入投遞碼 ...」），方便自己打字、唔掃碼亦唔撳連結
  嘅人。
- **複製連結**會將嗰條連結原封不動放入剪貼簿，並向螢幕閱讀器宣佈「連結已經複製到剪貼簿。」
- **QR 碼**用內置編碼器（同本機安全配對用嗰個一樣）編碼同一條連結，深淺色主題都係白底黑碼，四格靜區。
  佢嘅無障礙名稱係「邀請連結嘅 QR 碼」。**放大 QR 碼**，或者撳一下個碼，會打開大圖，方便手機喺遠啲
  掃描。
- **新連結**會叫容器整一個新投遞碼（`POST /api/station/drop-code`），用舊投遞碼嘅連結就會失效。
  `DROP_CODE` 固定咗投遞碼嘅話，呢個掣會停用，邀請會解釋點樣喺投遞網站改。
- Bambu Studio 由接收站狀態攞到目前嘅投遞碼之後，連結先會出現；喺嗰之前，邀請會講明佢等緊乜。

**投遞碼**一行會顯示同一個碼，旁邊有**新投遞碼**掣。

## 收到模型嘅時候

選項開咗嘅時候，Bambu Studio 每 5 秒檢查一次投遞網站。出錯之後會等 10、20、40，然後 60 秒先再試；
再次連到網站就會返去每 5 秒。

每個新檔案都會先下載，再檢查大小同網站列出嘅一樣、SHA-256 摘要同列出嘅一樣（有 `X-Content-SHA256`
標頭嘅話都要一樣），同埋檔名保留咗一個接受嘅副檔名，而且同列出嘅類型同內容吻合（3MF、STL、STEP、OBJ、
AMF）。內容檢查用返投遞網站自己嘅規則，所以網站收咗嘅模型，呢度永遠唔會拒絕：3MF 要有 ZIP 簽名；STL 要
啱晒二進制長度，或者係以 `solid` 開頭、有 `facet` 嘅 ASCII 文字；STEP 要有 `ISO-10303-21`；OBJ 要係有頂點行
（`v` 加空格或者 Tab，前面可以縮排）嘅文字；AMF 要係有 `<amf` 嘅 XML，或者 ZIP。開頭可以有 UTF-8 位元組
順序標記同空白，標記會喺頭 256 KiB 入面搵。

檔案會儲存喺資料資料夾嘅 `lan-model-drop/received/<id>/<檔名>`。啲位元組會先用 Bambu Studio 自己嘅臨時名稱
寫落去，之後先改名，所以寄件人揀嘅名永遠唔會被開嚟寫入；而且個資料夾一定要未存在（中途斷咗留低嘅空資料夾
會被取代）。檔名會先簡化做安全嘅基本名稱：資料夾部分、控制字元、`<>:"/\|?*`，同埋尾嘅點同空格都會拎走。
然後，Windows 會當成裝置嘅名稱會喺前面加底線。只要名稱第一個點之前嘅部分（去咗尾空格之後）係 CON、PRN、
AUX、NUL、CONIN$、CONOUT$、COM0 至 COM9 或者 LPT0 至 LPT9（大細楷都一樣），又或者 COM 或 LPT 後面跟住上標
1、2 或 3，Windows 就會開裝置而唔係開檔案，所以 `COM3 .x.stl` 會儲存做 `_COM3 .x.stl`。仍然用唔到嘅名稱，或者
會令路徑長過 259 個字元嘅名稱，會換做 `model.<類型>`，例如 `model.stl`。通知顯示嘅係簡化後嘅名稱。

之後會彈出通知「<寄件人> 傳咗 <檔案>（<大小>）」，或者「有人傳咗 <檔案>（<大小>）」，有兩條連結：

- **開啟**會行同拖放檔案入視窗一樣嘅載入流程，所以未儲存項目、或者將 3MF 當項目開嘅問題照樣會問。
  之後 Bambu Studio 會叫投遞網站刪除佢嗰份。
- **捨棄**會移除本機嗰份，再叫投遞網站刪除佢嗰份。

關閉通知，檔案會繼續等。邀請會顯示幾多個檔案等緊處理，**顯示出嚟**會再彈出佢哋嘅通知。檢查唔過嘅檔案會
被拒絕，並有警告講明原因，同時會喺投遞網站刪除。試咗三次都下載唔到嘅檔案會留喺投遞網站直到過期；將選項
關咗再開就會再試。從未開啟過嘅檔案，下次啟動時會喺資料資料夾移除，投遞網站仲有嘅話會再收到一次。開啟過嘅
檔案會保留佢個資料夾，因為項目可能指住佢；想將項目放去第二度，請用「另存項目」。Bambu Studio 之後永遠唔會
再寫入或者移除已開啟檔案嘅資料夾：投遞網站再列出嗰個檔案嘅話（因為刪除請求未成功），佢唔會再下載，只會叫
投遞網站刪除。

投遞網站未確認嘅刪除請求，會保存喺資料資料夾嘅 `lan-model-drop/pending-deletes.txt`（每行一個項目 id 同
投遞網站地址，最多 1000 個），所以重新啟動之後都仲喺度。每個刪除請求只會送去列出嗰個檔案嘅地址：地址改咗之後，
欠舊地址嘅刪除請求會等到再設返嗰個地址先送；新地址列出一個已經處理過嘅檔案，亦都會喺嗰度刪除。

## 安全同私隱

- 接收站金鑰係秘密。佢只會以目前 Windows 帳戶嘅 DPAPI 加密資料儲存（`CryptProtectData`，有用途熵，
  禁止使用者介面），放喺資料資料夾嘅 `lan-model-drop/station-key.dpapi`，永遠唔會寫入設定檔。第二個
  帳戶，或者喺第二部電腦嘅資料夾副本，都解唔開；所以完整備份資料資料夾時，只會帶走嗰份加密資料，永遠唔會
  帶走明文金鑰。其他系統會報告儲存用唔到，而唔會用純文字保存金鑰。
- 金鑰永遠唔會寫入記錄。請求只會帶 `Authorization: Bearer <金鑰>` 同 `Accept`：程式平時嘅額外標頭會
  被移除，唔會跟隨重新導向，傳輸追蹤亦都關閉。請求會直接去投遞網站，永遠唔會經
  `http_proxy`、`https_proxy` 或者 `all_proxy` 環境變數指定嘅代理伺服器。記憶體入面嘅金鑰副本用完會被覆寫。遮蔽咗嘅欄位可以用眼睛掣
  顯示；兩個欄位都唔會被擷取、記入歷史或者匯出。
- 經 `http://` 傳送嘅話，金鑰同檔案都冇加密。用 `http://localhost:8833` 嘅話，乜都唔會離開呢部電腦；
  投遞網站喺第二部電腦運行嘅話，就只喺你信任嘅網絡用，或者將佢放喺 `https://` 反向代理後面再用嗰個地址
  （證書會被驗證，所以代理要用一張呢部電腦信任嘅證書）。
- 所有網絡工作都喺一條背景執行緒做。結果只會經事件佇列、而且只喺主視窗仲存在嘅時候先到達視窗。關閉程式時，
  背景執行緒會喺視窗拆走之前停低：設定取消旗標、中止進行中嘅傳輸、喚醒執行緒再等佢完結。
- 唔會自動開啟、切片或者打印。冇任何分析或者遙測。

## 設定

| 鍵 | 意思 |
| --- | --- |
| `lan_drop_enabled` | 開關；唔係 `true` 就係關閉 |
| `lan_drop_address` | 投遞網站地址，預設 `http://localhost:8833` |
| `lan_drop_invite_ipv4` | 邀請連結揀用嘅私人區域網絡地址 |

  送去列出檔案嘅網站並且保存喺磁碟，同埋冇改變嘅輪詢唔會設定文字或者重新排版，等雙語模式嘅廣東話留喺即時
  更新嘅行度。每條規則亦都會對改動過嘅原始碼再行一次，證明佢真係會失敗。
- `node --test tests/lan_model_drop/station_container.test.mjs` 會經
  `tests/lan_model_drop/lan_model_drop_station_probe.cpp`，用接收站嘅純邏輯對住 `lan-model-drop/server`
  入面真正嘅投遞服務行一次：投遞每種類型嘅模型（包括位元組順序標記、縮排同 CR 換行）、讀狀態同收件匣、
  下載每個檔案再檢查大小、SHA-256 同內容、刪除佢、轉換投遞碼，再由 `DROP_PUBLIC_URL` 同區域網絡地址砌出
  邀請連結。佢亦都會傳送 Windows 當成裝置嘅名稱（`COM3 .x.stl`、`LPT1 .print.stl`、`CONOUT$.stl`、
  `COM¹.stl` 等等），投遞服務會照原樣列出，再檢查冇一個會成為寫入檔案用嘅名稱。佢需要投遞服務同 g++，
  冇嘅話會略過。
- `node --test tests/lan_model_drop/station_agreement.test.mjs` 會檢查兩邊接受嘅嘢係咪一樣：接收站會清理到
  乜都唔剩嘅檔名或者寄件人名稱（會調轉或者收埋文字嘅字元、零寬空格），投遞網站會喺寄件人仲喺網頁度嘅時候
  用 400 拒絕；`DROP_MAX_BYTES` 同 `DROP_QUEUE_MAX_FILES` 唔可以超過接收站自己嘅上限（每個模型 2 GiB、
  收件匣 1000 項，由 `LanModelDropModel.hpp` 讀出）；網站接受嘅每個 `DROP_PUBLIC_URL`，都會照網站報告嘅
  樣子放入邀請連結；網站最多 60 個字元嘅接收站名稱會完整顯示。以前呢幾樣全部都唔夾。
- `node --test tests/lan_model_drop/container_fixtures.test.mjs` 會重播由真正容器擷取嘅回覆。
  `tests/lan_model_drop/container_capture.py` 用 Docker Compose 建立 `lan-model-drop`，經無頭 Chromium
  入面真正嘅寄件網頁傳送每個樣本模型（3MF、ASCII 同二進制 STL、STEP 同 STP、OBJ、XML 同壓縮 AMF），再用
  網頁嘅標頭經 curl 傳多一次，照接收站嘅做法行接收站 API，再改晒所有設定第二次啟動容器，然後將每個回覆連同
  原始標頭行保存喺 `tests/lan_model_drop/container_fixtures/`。`lan_model_drop_container_interop_test.cpp`
  將佢哋交畀接收站嘅純邏輯，逐個欄位同判斷核對：狀態、每項收件匣記錄對比傳送嘅位元組同自己計嘅 SHA-256、
  每次下載嘅判斷（`judge_download`）同儲存、錯誤或者冇金鑰、唔存在同已移除嘅檔案、新嘅同固定嘅投遞碼
  （`classify_new_code`）、DELETE（`delete_settled`），同埋兩條邀請連結。同一批回覆亦都會經寄件網頁自己嘅
  結果規則同邀請讀取，而 curl 傳送嘅請求會同 Chromium 傳送嘅協定標頭比較。
- 接收站原始碼喺 Linux 語法檢查編譯得到，DPAPI 金鑰儲存同網絡介面列舉亦都用 MinGW 交叉編譯器編譯得到；
  無障礙事件只係人手審閱過。未試過喺真正網絡上，用已建置嘅 Windows 程式連接真正嘅投遞網站。
