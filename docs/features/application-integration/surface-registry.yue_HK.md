# 原生介面登記表

`FeatureServices::SurfaceRegistry::instance()` 用弱參照記低存活嘅 wxWidgets 介面。每個要個別存取嘅介面都要呼叫 `register_surface(window, "semantic-id")`。ID 最多 256 個位元組，只接受 ASCII 字母、數字、`_`、`-`、`.` 同 `/`，唔可以包含使用者內容。兩個存活介面唔可以用同一個 ID；明確指定嘅 ID 喺介面重建後仍然穩定。

登記時、閒置時，以及資料收集端查詢權限前，登記表都會發現子視窗；查詢前嘅發現係同步進行。自動產生嘅 ID 由上層 ID、原生類別名稱同第一個未用序號組成。現有子視窗會保留 ID；同類別嘅替代元件可重用已銷毀子視窗嘅位置。如果集合會調換次序，就要明確指定有意思嘅 ID，因為結構位置無法喺任意排序後識別同一份文件或者項目。自動發現嘅子視窗之後亦可以升格為明確登記嘅介面。

全部發現嘅視窗都會交畀現有 `ElementStyle` 接管外觀，唔會另裝第二個內容選單。`surface_id()` 提供穩定外觀 ID，已有覆寫同變更通知都會沿用。

## 顯示文字

用 `record_label()` 同 `record_tooltip()` 登記公開原文。更新顯示時，先由 `I18N` 翻譯已儲存嘅原文，再套用只影響顯示嘅個人用字。唔會由畫面上已翻譯嘅標籤反推原文。個人用字載入或者清除後，觀察器會重新套用原文。`refresh_presentation()` 亦會令版面重新計算並套用外觀。

固定事實說明用 `record_label_renderer(window, original, renderer)`，每次更新都由指定嘅無狀態轉譯器處理原文，結果直接顯示，唔再加語氣或者個人用字。元件擁有者要提供真正嘅事實文字翻譯函式，唔可以讀欄位值、推斷原文或者虛構帳戶狀態。空轉譯器會被拒絕，並保留之前來源。之後再呼叫 `record_label()` 就可以還原一般顯示途徑。兩種登記方法都唔接受敏感介面同文字輸入元件；動態代碼、日期同狀態標籤唔會登記。

原文必須明確登記。唔會推斷或者改寫文字輸入、文件內容、檔名、自繪元件、選單同清單項目。呢啲內容要由各自負責嘅元件提供知道來源嘅轉接器。登記表唔改已儲存文件、匯出文字或者翻譯目錄。

`record_name(window, public_source)` 透過 `SetName` 設定已翻譯嘅原生無障礙名稱，遮罩欄位同明確標示敏感嘅元件都適用。只可提供「確認密碼」等中性用途文字，唔可以用輸入內容。佢唔會讀取現有值或者標籤，唔會更改值，亦唔會降低敏感等級。將欄位標示為敏感會清除標籤同提示原文，但保留明確登記嘅中性名稱。

冇呼叫 `record_label()`，標籤就一直由元件自己管理。`clear_label_source()` 移除之前登記嘅原文但保留現有標籤，等元件繼續自行更新日期、代碼或狀態，唔會喺下次更新顯示時被覆寫。名稱同提示文字來源各自獨立。

## 敏感介面同資料收集檢查

顯示敏感介面前要呼叫 `register_sensitive()`。指定後，喺該原生視窗銷毀之前都有效。即使未到閒置發現階段，遮罩 `wxTextCtrl` 欄位亦會按密碼樣式直接識別。歷史記錄、匯出同截圖端必須喺收集內容之前即時查詢相應權限。不明視窗、未登記嘅外層子樹、有敏感上層或者敏感後代都會被拒絕，因此父視窗截圖唔可以連受保護子項目一齊收錄。已銷毀視窗嘅弱參照會被移除。

喺 Windows，如果頂層視窗包含敏感內容，登記表會嘗試對整個頂層視窗呼叫 `SetWindowDisplayAffinity` 同 `WDA_EXCLUDEFROMCAPTURE`，再讀返結果。`capture_protection()` 區分已套用、不支援、失敗同唔需要。其他平台會報不支援。可選觀察器只發佈狀態變更，唔包含介面標籤或內容。敏感內容消失後會還原之前嘅設定。呢個額外作業系統機制唔保證攔到所有截圖途徑，亦唔取代收集端檢查。單憑中繼資料唔足以保護圖片、匯出或者歷史記錄。

## 歷史識別碼

`history_identity()` 只會為准許記錄歷史嘅介面回傳獨立嘅 32 位小寫十六進制 ID。對照表儲存喺固定 `Slic3r::data_dir()` 下面嘅 `surface-identities/identities.json`，用公開結構 ID 做鍵，唔用標籤或者輸入值。新 ID 使用隨機位元組，查核冇碰撞並完成原子檔案取代後先會發佈。跨程序鎖避免同時更新時資料遺失。上限係 4096 個 ID、1 MiB。讀取時拒絕重複鍵、不明欄位、過多巢狀層次、無效值同重複識別值。儲存無效、鎖爭用或者寫入失敗就回傳空 ID，收集端必須停止記錄。敏感介面永遠唔會經呢個 API 攞到 ID。

## 驗證同限制

原生整合測試 `tests/feature_services/surface_registry_tests.cpp` 涵蓋不明視窗、動態子元件、替代 ID、明確升格、重複 ID、真實外觀接管、原文更新、敏感繼承、整個上層排除、銷毀同遮罩輸入。需要正式 wxWidgets、外觀、翻譯、個人用字實作同原生顯示環境。存在測試原始碼唔代表已經跑過；整合負責人要記錄原生建置同執行結果。

登記表只限 UI 執行緒使用。每個內容收集位置都要接駁。已收集嘅檔案唔受佢保護，佢亦唔會喺一般元件自動識別敏感文字，未登記介面唔屬於覆蓋範圍。
