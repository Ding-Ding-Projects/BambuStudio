# 原生選單同打印機選擇嘅生命週期

準備工作區嘅打印機卡會透過明確指定嘅可見焦點擁有者開啟預設下拉選單。
選擇項目時，會先保存該行資料，再關閉子選單同根選單。關閉通知會先於
選擇回呼執行。弱參照會阻止向已銷毀嘅擁有者傳送選擇事件，而項目版本
會拒絕關閉期間已重建嘅清單選擇，即使新舊行嘅外觀完全一樣。
佈局、點陣圖同旗標更新唔會改變呢個結構性項目版本。

阻塞式 Material 選單會先結束巢狀事件迴圈，安排彈出視窗銷毀，然後先傳送
所選命令。子選單命令會保留擁有事件綁定嘅選單，並透過仍然存在嘅頂層
呼叫視窗傳送。自動加入嘅外觀編輯命令會先另外保存元素同弱錨點，再移除
臨時選單項目。

關閉時所需嘅傳送狀態會喺還原焦點或平台關閉之前保存，因為兩者都可能
同步銷毀彈出視窗。其餘關閉同傳送步驟會由弱參照保護。重用嘅選單會喺
命令傳送之後還原原先嘅呼叫視窗，唔會一直留住臨時擁有者。

搵唔到符合嘅型號變體時，打印機選擇會保留目前打印機。取消未儲存預設
對話框會停止套用設定、重新分配打印板、修改已儲存映射同自動沖刷計算。

實體耗材行會對應設定槽索引。選單回呼讀取目前映射，唔會沿用該行建立時
嘅原始索引。刪除會先解析一次目標，再確認該目標；如果確認期間槽清單
改變，就會中止。混色槽身份由專案旗標決定，唔係由可見實體行數決定。
最後一個實體耗材仍然受保護。銷毀行時，由父視窗負責同層子視窗嘅清理，
組合框唔會重複安排銷毀同一批子視窗。

延後執行嘅行標題佈局工作會排入側邊欄本身，所以銷毀側邊欄亦會移除
待執行回呼。每次刪除都會按實體槽映射重建行，包括混色槽交錯排列嘅情況。
編輯會按目前設定槽搵返實體行，因此交錯嘅混色槽唔會令有效編輯操作變成
越界行索引。取消或已過時嘅編輯選擇會保留目前編輯器；成功切換之後會
停止迭代，避免繼續讀取已重建嘅行清單。

## 驗證同限制

`dropdown_lifecycle_tests` 會將實際生產程式嘅事件傳送同組合框轉接函式，
連同可重現嘅事件同生命週期替身一齊編譯。涵蓋根選單／子選單次序、
過時項目版本、只更新測量之後仍然有效嘅選擇、停用行、無效行、關閉期間
銷毀擁有者、關閉子選單時銷毀根選單，以及選擇時銷毀彈出視窗。
呢啲測試驗證回呼次序同擁有權決定，亦會編譯生產程式嘅選單焦點同關閉
函式，測試還原焦點、平台關閉同關閉回呼期間嘅銷毀、只傳送一次關閉通知，
以及阻止喺彈出視窗呼叫堆疊內傳送命令。呢啲確定性測試唔能夠代替原生
wxWidgets 後端互動驗證。

此測試目標亦會編譯生產程式嘅編輯函式，涵蓋交錯槽身份、取消、過時槽
選擇同行重建。本次工作停止本機編譯之後，新增案例仍然等待託管建置驗證。

`node --test ui-md3/tests/native-lifecycle.test.mjs` 提供補充來源契約同刻意
破壞嘅負向案例。完整原生建置同真實互動證據，必須另外涵蓋 P1S/H2C 切換、
重複選擇、未修改同已修改預設、儲存／捨棄／取消結果，以及實體／混色耗材
刪除。來源修改同確定性測試唔代表已確認執行時根因，亦唔代表已成功擷取畫面。
