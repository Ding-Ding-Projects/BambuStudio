# 準備邊欄中嘅流程設定

準備邊欄展示流程設定喺兩個模式：

- **簡單**（預設）， 緊湊 MD3 流程卡：一個設定搜尋丸、流程預設 SelectField、一個 `質素 / 強度 / 支持 / 其他` 分段控制、一些精選行同埋一個**進階設定**按鈕。
- **進階** ， *完整*流程設定樹（`ParamsPanel`、重新父化到邊欄），攜帶 `全球` / `物件` 模式開關、類別標籤條同埋每個選項行。一個**簡單設定**欄翻轉返回。

選擇保留喺應用配置鑰 `sidebar_process_advanced`。

## 為乜嘢邊欄喺進階模式中擴展

完整樹係*設定標籤*佈局。每個選項行係一個標籤加一個值欄位，兩個半都唔重流：行保留佢嘅自然寬度或佢得到切割。喺密度預設中現場測量，`層高` 行佈置**1234 px 寬喺 348 px 邊欄內**。

所以翻轉到進階要求停靠 `ADVANCED_SIDEBAR_WIDTH`（480 dip）透過 `Plater::request_sidebar_width()`。該要求係刻意弱嘅：

| 行為 | 原因 |
| --- | --- |
| 限制到**55% 嘅幀** | 一個狹窄視窗保留一個可用嘅 3D 畫布。 |
| 從唔低於密度預設 | 進階模式必須唔使邊欄*更窄*。 |
| `grow_only` 喺進入時 | 一個邊欄你已經拖動更寬係留單獨。 |
| 在明確翻轉到**簡單**時只縮小 | 該翻轉係一個緊湊寬度嘅要求。 |
| 窗簾保留可拖動；拖動寬度係由現有閒置處理程序保留嘅 | 強制寬度係一個起點、唔係鎖。 |

啟動重申寬度喺第一個**排版**大小事件、唔係喺構造函數：`Plater::priv` 構造函數執行早於幀有寬度、同埋一個要求喺該點被製作限制到緊湊預設。`request_sidebar_width()` 返回 `false` 當幀仍然太細去對比大小時，所以呼叫者重試代替錨定一個壞值。

## 水平滾動係後擋

寬度單獨唔係一個保證 ， 一個非常狹窄視窗、一個大顯示尺度或最長本地化字串仍然可以溢出。邊欄身體因此增長佢嘅**虛擬寬度**當內容確實唔能壓縮、同埋有一個真實水平滾動條去增長到（`update_sidebar_scroll_body()`）。

任何*能夠*重流嘅仍然接收客戶端寬度，所以緊湊卡從唔獲得一個滾動條佢哋唔需要。`update_sidebar_scroll_body()` 也攜帶一個重入守衛：`SetVirtualSize()` 可以添加或移除一個滾動條、重新大小化客戶端區域同埋通過邊欄自己嘅 `EVT_SIZE` 重新進入幫手。

> [!IMPORTANT]
> 之前、身體被建立 `wxSHOW_SB_NEVER` 用於水平欄，帶 x-滾動率
> 嘅 `0` 同埋 `EnableScrolling(false, true)`。剪輯嘅選項值唔係單純離屏，
> **冇量嘅滾動可以到達佢哋。**

## 飢餓標頭失敗呢個修復

喺緊湊寬度標頭行被超額認購。當一個 `wxBoxSizer` 行唔能支付每個最小佢支付固定項全部同埋交付**零**給不論跨越邊界、所以 `流程` 標題同埋**比較預設**按鈕唔係剪輯，佢哋係*缺失*、留下 `進階` 楔入對 `全球` / `物件` 開關。

呢個係同一失敗模式，移除印表按鈕（見 `HANDOFF.md` §3.3）。一個飢餓控制留冇視覺間隙、所以「冇任何嘢超越」唔係證據，冇任何嘢係缺失。

## 搜尋

兩個模式攜帶一個設定搜尋丸接線到相同 `OptionsSearcher` ， 相同對話框、相同 `.*` 正則表達式開關同埋調整構建彈出作為每個其他搜尋表面。緊湊卡嘅欄隱藏連同卡、所以進階模式有佢自己喺**簡單設定**欄；否則表面，帶最多選項喺佢入面，會係唯一設定表面，冇搜尋。

範圍係 `Preset::TYPE_INVALID`、所以一個查詢跨越每個索引預設類型同埋啟動一個結果跳到主樹入面擁有選項。

## 物件操控

物件操控卡開始**隱藏**同埋出現，當一個選擇使佢嘅值真實（`GizmoObjectManipulation::Cache::is_valid()`），然後隱藏再次，當選擇清除。帶冇咩嘢被選擇每個單元讀為 en dash、所以卡係充電一個螢幕側邊欄高度去說冇嘢。佢嘅分隔符係隱藏同埋展示，帶佢、所以冇孤立規則係左後面。
