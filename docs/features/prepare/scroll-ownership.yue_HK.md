# 準備設定捲動

準備邊欄嘅主體負責嵌入式設定頁面嘅垂直同水平捲動。頁面會將焦點同搜尋結果嘅顯示要求交畀主體，並停用自己嘅捲動範圍。獨立預設編輯器保留有界限嘅頁面視窗同自己嘅捲軸。

顯示目標時會獨立處理兩個方向。比視窗闊嘅群組唔會再阻止垂直顯示；超大目標會露出前端。邊欄重新排版時保留目前像素起點，內容縮細時由捲動輔助器限制位置，並喺預留捲軸空間後重新讀取客戶區。每個視窗各自限制同步尺寸事件遞迴，唔會壓制另一個畫面嘅排版。

設定行嘅最小闊度超過視窗時，仍然可以水平捲動。呢個改動唔會重新設計嗰啲選項行。

驗證：現有捲軸測試通過10項檢查，邊欄闊度測試通過4項，prepare-scroll-owner.test.mjs 通過8項。刻意移除顯示委派會令擁有權檢查失敗，還原後通過。算術測試經語法轉換後執行正式程式嘅純量運算。呢啲係原始碼同算術檢查，唔係原生事件或實際畫面排版證據。原生建置、滑鼠滾輪路由、最後一行存取、搜尋與焦點顯示、調整尺寸、類別與分頁切換、語言同DPI組合，仍然需要固定版本嘅執行驗證。

到達嵌入式頁面嘅滾輪事件會先複製畀外層擁有者，避免內層零範圍捲動輔助器吞咗事件。副本保留滾輪增量、方向同修飾鍵，而且只傳送一次。顯示擁有權只接受祖先視窗，並使用弱參照，避免循環或保留已銷毀嘅主體。切換區段時先整理新內容範圍，再回到頂部並要求邊欄重畫。

針對性原始碼與算術檢查而家包括滾輪路由同切換次序，但唔能夠證明原生事件傳送。整合建置仍須驗證頁面控制項同空白位置上嘅滾輪捲動、焦點與搜尋顯示、最後一行存取，以及由非零位置切換區段。

嵌入式頁面背景本身有焦點時，冇修飾鍵嘅導航鍵會複製畀外層捲動擁有者。內層鍵盤捲動輔助器已停用。有焦點嘅文字欄位同類別控制項保留自己嘅按鍵處理；修飾鍵同其他按鍵會照常交畀後續處理。

修復前嘅原生量度記錄咗嵌入式 TabPrint 分配高度302 px，但自然標題高度係152 px，下一個頁面由 y=308 開始。嵌入式標題而家喺頁面配合內容時重新量度，將高度限制喺自己排版器嘅內容高度。獨立預設編輯器唔會執行呢個限制。仍須喺已設定、冇首次設定對話框嘅設定檔重複量度，並檢查調整尺寸後換行嘅類別行。
