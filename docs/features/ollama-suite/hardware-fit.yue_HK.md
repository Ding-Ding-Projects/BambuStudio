# 硬件適配證據

本地 Ollama 套件嘅「Models」部分會俾每個模型四個評估結果之一：**運行順暢**、**可以運行但有限制**、**唔太可能**或者**未知**。評估只係用量度到嘅事實同已公佈嘅模型資料計出嚟嘅估算，唔會保證下載咗就一定運行得到，亦都唔會由模型名稱推斷任何嘢。

## 量度啲乜

喺「Models」部分揀「Refresh runtime」或者「重新量度硬件」。按鈕下面嘅面板就會列出評估用到嘅每項事實，同埋量度時間：

- **系統記憶體**：Windows 報告嘅可用同總實體記憶體。
- **處理器架構**：x86_64 或者 arm64。
- **顯示卡**：透過 DXGI 讀取每張硬件顯示卡嘅名稱、驅動程式版本同專用記憶體。軟件顯示卡會略過。可用記憶體係專用記憶體，上限係 Windows 而家容許嘅預算，所以其他程式佔用緊嘅記憶體唔會計入。
- **GPU 後端**：Ollama 用唔用得到 GPU。只有 Ollama 自己先證明到，所以套件會記錄 Ollama 對已載入模型嘅報告（GET `/api/ps`）：嗰個模型有幾多位元組放喺 GPU 記憶體。呢個記錄會連同當時嘅顯示卡、驅動程式版本同 Ollama 版本一齊保存。更新驅動程式、換顯示卡或者升級 Ollama 之後，記錄就唔再適用。
- **模型資料夾同可用空間**：Ollama 將模型放喺邊，同埋嗰度仲有幾多可用空間。

想 Ollama 報告 GPU 用量，就要先載入一個模型（例如傳送一條對話訊息），然後趁模型仲載入緊揀「Refresh runtime」。

## 搵模型資料夾

Ollama 會將模型放喺 `OLLAMA_MODELS` 設定指定嘅資料夾；冇呢個設定嘅話，就放喺使用者設定檔入面嘅 `.ollama\models`。套件會檢查使用者設定、電腦設定、本應用程式自己嘅環境，同埋預設位置。

如果 Ollama 列出嘅已安裝模型清單檔喺某個資料夾入面搵到，嗰個資料夾就算已確認。仲未安裝任何模型嘅時候，就用設定指定嘅資料夾；如果唔同來源指向唔同資料夾，就用佢哋之中最少嘅可用空間。如果已經安裝咗模型，但係冇一個資料夾有佢哋，資料夾就仍然未確認，儲存適配係**未知**。請檢查運行緊嘅 Ollama 嘅 `OLLAMA_MODELS`，重新啟動 Ollama，再揀「Refresh runtime」。

## 估算設定

硬件面板旁邊有兩個選擇器，決定估算包括幾多上下文記憶體：

- **估算用嘅上下文長度**：2048 至 131072 個 token。建議由 4096 開始。如果數值大過某個模型已核實嘅上下文上限，嗰個模型就會用返佢嘅上限。
- **上下文快取精度**：16 位元（預設，亦係最大），或者 `OLLAMA_KV_CACHE_TYPE` 嘅 8 位元同 4 位元數值。揀返你運行 Ollama 時用嘅數值。

設定會儲存喺套件自己嘅資料夾。改任何一個，每個評估結果都會即刻重新計算。

## 點樣得出評估結果

1. 一定要有模型嘅準確大小同模型資料夾嘅可用空間。未安裝嘅模型需要佢嘅大小再加百分之十預留；可用空間少過呢個數就係**唔太可能**。
2. 跟住要有記憶體證據：量度到嘅系統記憶體、處理器架構，同埋 `/api/show` 提供嘅模型參數數量、量化、上下文上限同注意力結構。未安裝嘅模型仲未有呢啲運行資料，所以要安裝同檢查之後，記憶體適配先唔係**未知**。
3. 記憶體估算 = 模型大小，加百分之二十俾運行環境，再加上下文快取。上下文快取 = token 數量 × 層數 × 鍵值注意力頭數 × （鍵維度 + 值維度）× 所揀精度每個數值嘅位元組。
4. 有 Ollama 嘅 GPU 證據：估算裝得落可用 GPU 記憶體 → **運行順暢**；裝得落系統記憶體 → **可以運行但有限制**（部分卸載到處理器，唔預測速度）；否則**唔太可能**。
5. 冇呢個證據就唔計 GPU：估算裝得落系統記憶體 → 用處理器**可以運行但有限制**；否則**未知**。

缺少嘅資料永遠唔會當成零。詳情面板會列出評估結果、儲存同記憶體數字、上下文同快取大小、每個適用嘅原因，同埋量度時間。本地伺服器設定檔嘅啟動前檢查都用同一個評估，不過用設定檔自己嘅上下文長度。

## 驗證

`tests/ollama_suite_model/ollama_suite_model_tests.cpp` 測試上下文快取計算、清單檔位置、資料夾確認、後端證據同佢點樣失效、四個評估結果喺記憶體、GPU、磁碟同設定改變時嘅變化，同埋淨係改名唔會改變評估結果。`tests/ollama_suite_model/ollama_fit_wiring.test.mjs` 檢查對話框同用戶端有冇將呢啲量度交俾每個評估。DXGI 同登錄檔讀取只會喺 Windows 運行，仍然要喺建置好嘅應用程式度觀察。
