# 模型商店篩選同解釋

「Models」部分會列出上次已核實嘅官方目錄入面每一個變體，同埋呢部電腦已安裝嘅每一個模型，兩邊都唔會遮住對方。搜尋、篩選、分組同排序都係對成個變體層級嘅清單操作。

## 搜尋

搜尋欄會比對模型名稱、架構系列、量化同已核實嘅功能。預設係純文字；旁邊嘅正規表示式建立器可以將同一個欄位轉做錨定嘅正規表示式。

## 篩選

每個篩選都係由清單本身填入嘅選擇器，永遠唔係自由輸入欄。每個一開始都係**任何**，揀「清除篩選」就可以一次過將全部還原做**任何**。

| 篩選 | 數值 |
| --- | --- |
| 狀態 | 運行緊（而家已載入記憶體）、已安裝（包括運行緊嘅模型）或者只喺目錄。 |
| 系列 | 清單入面每個項目 `family:tag` 冒號前面嘅模型名稱。 |
| 變體 | 所揀系列已公佈嘅標籤。未揀系列嘅時候，選擇器會停用，提示會叫你先揀系列：一個系列有幾十個標籤，成個目錄就有幾千個。 |
| 功能 | Ollama 為已安裝模型報告嘅每個功能，加上**功能未核實**。 |
| 量化 | Ollama 為已安裝模型報告嘅每種量化，加上**量化未核實**。 |
| 大小 | 少過 2 GiB、2 至 8 GiB、8 至 32 GiB、超過 32 GiB，或者**仲未知道大小**。 |
| 硬件適配 | 運行順暢、可以運行但有限制、唔太可能或者未知，按目前嘅硬件量度同估算設定為每個項目計算（睇[硬件適配證據](hardware-fit.md)）。 |

功能、量化同大小只會嚟自已核實嘅資料。「Refresh runtime」會為每個已安裝模型讀取 `/api/show`，所以佢哋嘅功能、量化同注意力結構都知道。目錄項目要安裝咗先有呢啲資料，所以會列喺**未核實**嘅數值下面；要揀咗佢，先會由官方登記庫讀取準確大小。任何嘢都唔會由模型名稱推斷：就算目錄項目嘅名稱好似同圖片有關，都仍然係**功能未核實**。

## 分組同排序

「分組」會按系列、狀態、硬件適配、量化或者大小，將清單排喺標題下面。每個標題會顯示分組同入面有幾多個變體。分組會按有用嘅次序排列：運行緊先過已安裝，已安裝先過只喺目錄；適配最好嘅先；大小細嘅先；系列同量化按字母排，未核實嘅放最後。

「排序」會喺每個分組入面按名稱、系列、大小（細嘅先或者大嘅先）或者硬件適配（最好嘅先）排列變體。未知大小無論邊個方向都排最後，因為佢哋係未量度，唔係細。

## 揀之前嘅解釋

- 篩選下面嗰行會講顯示緊成個清單入面幾多個變體，然後解釋每個生效嘅篩選：狀態代表乜、系列同變體係乜、所揀功能做到乜、所揀量化每個權重用幾多位元同會損失幾多質素、大小範圍需要幾多空間，同埋所揀評估結果嘅意思。
- 揀一個標題，會用同樣方式解釋嗰個分組。
- 揀一個變體，會即刻喺任何下一步之前解釋佢：佢嘅系列同準確標籤、狀態、每個已核實功能、量化、大小同佢喺模型資料夾需要嘅可用空間（大小加百分之十預留），同埋佢目前嘅硬件適配結果代表乜。之後嘅檢查會再加上評估結果背後嘅完整證據。

## 驗證

`tests/ollama_suite_model/store_query_tests.cpp` 測試每個篩選單獨使用同配合搜尋、未核實嘅數值、每種分組同佢有計數嘅標題同次序、各種排序（未知大小排最後），同埋由清單得出嘅選擇器數值。`tests/ollama_suite_model/ollama_store_wiring.test.mjs` 檢查原生選擇器、佢哋嘅無障礙名稱、停用變體選擇器講明嘅條件、各項解釋，同埋冇寫死任何模型名稱，亦冇喺名稱入面搵意思。
