# Hidden browser verification

`ui-md3/scripts/site-wording-runtime.mjs` composes a committed candidate, hashes every output file, launches a fresh Microsoft Edge guest profile through the installed cheap hidden-desktop route, and requires the entire debugging target list to contain exactly one intended page. It calls the canonical `verify-edge-target.mjs` before each interaction batch and each capture. It exercises a neutral local JSON upload, reload persistence and clear, then records desktop and emulated-mobile English, Cantonese and bilingual settings states in light and dark themes. Page-only PNG captures are explicitly identified as such. A physical keyboard, physical touch device and display scales above 100% are not claimed by this focused script.

The caller supplies the installed cheap CLI, optional direct Python entrypoint for that same installed route, console-free Python interpreter, Edge executable, canonical target verifier and a new private run directory. The server binds only loopback, rejects path traversal and symlink escapes, and bounds individual resources to 16 MiB. The output includes a hashed manifest, candidate-bound build receipt, exact-page receipts and an ownership ledger. It never reuses a browser profile or target.

No real personal vocabulary is used in captures. A neutral test fixture exists only in the private run directory and is cleared before any retained pixels. The original filename is not saved by the page. Runtime raw metadata remains private until reviewed and exported as a sanitized evidence summary.

The bounded attempts covered console Node, console-free Python, GUI-first ordering, and the installed route's direct Python entrypoint. No browser target or pixels were produced. Normal-shell static serving succeeded, which does not satisfy the hidden launch boundary and was used only for diagnosis. Each owned attempt recorded process and port absence, removed its absent or owned profile, and closed its named desktop. Source tests passed; browser interaction, responsive layout, accessibility, playback and captures remain unverified. Repeating the same launch without a relevant route repair is not useful verification.

The script stops on a failed exact-page proof and never chooses a matching page from a contaminated list. Cleanup uses a normal browser-close request, revalidates saved creation time and executable before any PID fallback, verifies owned process and port absence, and removes only a realpath-contained profile. A failed cleanup leaves its ledger and does not claim completion.
