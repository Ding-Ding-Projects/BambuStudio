# 更新日誌檢視器

呢個分支已發佈嘅每一個發佈版本，最新優先 ， 唔係只有最新嘅。檢視器：[`ui-md3/site/changelog.js`](../../../ui-md3/site/changelog.js)。資料：[`ui-md3/site/changelog.data.js`](../../../ui-md3/site/changelog.data.js)，由 [`ui-md3/scripts/build-changelog.mjs`](../../../ui-md3/scripts/build-changelog.mjs) 生成。

> 桌面應用程式有佢自己嘅檢視器超越相同事實 ， **説明 ▸ 有咩新 / 更新日誌…** ， 由 `resources/changelog/changelog.json` 提供，`scripts/changelog/export-app-changelog.mjs` 用呢個指令碼嘅解析生成佢。睇 [應用程式內更新日誌檢視器](../windows/changelog-viewer.md)。

## 內容嚟自邊度

檢視器裏冇野係手寫嘅。

- 版本、名稱、碟、發佈日期、發佈 URL、提交、CI 執行連結同附加檔案連同佢哋嘅位元組大小嚟自 GitHub 發佈 API。
- 發佈底下嘅更改行係**該發佈版本標籤同前一個發佈版本標籤之間嘅提交主題**，從 `git log` 讀取。
- 每一行嘅類別徽章從提交主題嘅前導動詞機械推導（`fix…` → 修復、`add…` → 新增、`remove…` → 移除、`document…`/`handoff…` → 記錄，否則變更）。檢視器喺頁面上講明呢個推導，所以一個未正確分類行讀起嚟像映射人工製品而唔係一個聲明。
- 一個喺其範圍冇提交嘅發佈版本講住咁。一個標籤指向與其前身**相同提交**嘅發佈版本講*該個*反而 ， 一個不同事實，同兩者中唯一實際被檢查嘅。最舊發佈版本講佢冇更舊發佈版本去比較對抗。三個都冇被填充物填充。

喺本地用 `node ui-md3/scripts/build-changelog.mjs` 重新生成。**CI 喺部署時從發佈 API 重新生成佢**，喺 `continue-on-error` 下，帶著已提交檔案作為中斷備用 ， 所以已發佈網站列出每個發佈版本，包括喺檔案上次被提交後發佈嘅。

一個已發佈發佈版本亦都重新部署網站，所以佢出現，唔需等待下一個推 ， 但唔係直接。呢個分支上嘅 `github-pages` 環境只接受來自 `master` 嘅部署，同 `release` 事件喺**標籤**參考執行，所以部署工作喺其第一步前被拒絕：一個三秒失敗冇步驟同冇記錄。佢喺 12 次中 12 次嗰樣失敗，之前冇人留意，同佢承諾嘅重新整理永遠冇發生一次。release 事件現在去 `redeploy-on-release` 工作，唔持有環境同簡單派遣呢個工作流程喺 `master` 上；該執行著陸作為 `workflow_dispatch` 同平常部署，同佢保持佢自己嘅並發組，所以一個發佈版本唔可以取消一個被做真實工作嘅部署。[`ui-md3/tests/site.test.mjs`](../../../ui-md3/tests/site.test.mjs) 斷言該形狀，同佢裏面每一個斷言被變異驗証。

關於該修復嘅兩個野值得明確講，而唔係稍後發現。

**佢唔係追溯性。** `release` 事件執行工作流程檔案，因為佢存在喺**標籤嘅**提交，唔係因為佢存在喺 `master` 上。喺老於修復嘅提交標籤嘅發佈版本保持用舊方式失敗，直到佢哋排隊 ， `md3-v58` 通過 `md3-v61` 全部做，喺修復著陸後。所以一個紅色發佈版本執行唔係自動迴歸；首先檢查佢嘅標籤係咪早於 `5340bd466`。

**佢被驗証。** `md3-v62`，喺 `d9159322e` 標籤，係第一個標籤帶著修復嘅發佈版本，同佢係唯一喺呢個儲存庫歷史上冇失敗嘅發佈版本執行（17 次執行、16 次失敗、1 次成功）。`redeploy-on-release` 執行同 `deploy` 被略過，記錄讀 `Dispatched a master-ref Pages deploy for md3-v62`，同一個 `workflow_dispatch` 執行喺十秒後出現喺 `master` 上。

**`GITHUB_TOKEN` 可以派遣。** 呢個頁面嘅早期版本講佢唔可以；該係錯誤。GitHub 嘅遞迴觸發防止豁免 `workflow_dispatch` 同 `repository_dispatch`，佢哋「永遠建立工作流程執行」。真實需求係 `actions: write`。`TOKEN_GITHUB` 導導鏈只係所以派遣被歸咎於擁有者而唔係 `github-actions[bot]`，同 `GITHUB_TOKEN` 係最終備用，所以工作冇 PAT 全有效。

故意**冇新鮮度門**。需要已提交檔案係當前看起嚟整潔並係一個陷阱：每個發佈版本 CI 發佈令佢按定義陳舊，所以下一個頁面部署會失敗，直到一個人手動重新生成佢。`--check` 仍然存在作為本地便利同站退出（0 結束），當 GitHub API 無法使用時。

## 一個日曆：UTC

一個發佈版本時間戳係 UTC 即時，同一個發佈版本被歸檔嘅日子係佢嘅 UTC 日子。呢個檢視製作嘅每一個界限因此亦都係 UTC 日子 ， 預設、日曆單格、鍵入日期同匯出頁眉全部同意。從本地日曆建造界限反而放最新發佈版本外面「最後 7 日」，對於任何人西方格林威治，呢係那類虫唔會只為別人重現。

## 日期篩選

- **鍵入日期。** `From` 同 `To` 欄位接受一個純 ISO 日期（`2026-07-28` 同 `2026-7-8`）或訪客自己嘅地區格式，其欄位順序從 `Intl.DateTimeFormat` 讀取，而唔係假設。唔解析嘅輸入 ， 包括不可能日期，好似 `2026-02-30` ， 被報告內聯並**留下篩選同鍵入文字都唔動**。
- **日曆。** 每一個欄位開啟一個月格，帶著前/後月按鈕、一個月選擇同一個年選擇去跳轉，同當前範圍突出顯示。選擇一個日子會將開始放喺結束之後，交換佢哋，反而唔係空白檢視。
- **預設。** 全部時間、最後 7、30 同 90 日。

## 搜尋

搜尋列係共用元件：純文字預設、明確選擇加入正則表達式、完整構建器一個按鈕走，帶著更新日誌本身作為構建器嘅樣本。佢比對標籤、名稱、版本、兩個碟名稱、限定符、提交同每一個更改主題。

搜尋同日期篩選**組合**：縮小一個永遠唔會擴大另一個，同計數行永遠講「N 的 M 發佈版本」。當兩者一起比對冇野時，空白狀態坦白講咁，而唔係顯示未篩選列表。

## 複製同匯出

**複製檢視**將當前篩選檢視放喺剪貼簿；如果瀏覽器拒絕剪貼簿存取，文字被選擇反而，同通知講去按 <kbd>Ctrl</kbd>+<kbd>C</kbd>。**匯出 Markdown** 下載恰好已顯示，喺一個檔案命名作用範圍，其頁眉講源、匯出範圍、活躍搜尋、發佈版本數量匯出出嘅總計，同類別推導。
