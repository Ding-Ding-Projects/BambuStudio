# 本機檔案轉換器

轉換器由一個原生目的地面板、一個耐久嘅本機佇列、一個中介程序同一個獨立嘅離線工作程序組成。佢會保留來源檔案，永遠唔會取代已經存在嘅目的地。輸出資料夾要明確揀選。

## 可用轉接器同限制

目錄永遠會顯示文件/PDF、圖像、音訊、影片、封存檔、結構化資料/試算表、程式碼/文字同二進位編碼。每個分類都有獨立嘅本機搜尋欄，同共用嘅錨定正則表達式建構器。不可用嘅格式會繼續顯示，並註明確切原因。

已實作嘅轉換有：十六進位同 RFC 4648 Base64 編碼/解碼、UTF-8 LF/CRLF 換行標準化、JSON 格式化、長方形 CSV/TSV 字串表格同 JSON 之間互轉、24 位元冇壓縮 BMP/P6 PPM 互轉、單一項目 ZIP 建立/解壓，以及 [PDF 操作](pdf.md)。

輸入偵測靠位元組，唔靠副檔名。JSON 會拒絕重複鍵、過深嵌套同無效編碼。格式化會保留原本嘅數字字面值同字串轉義位元組，包括超出二進位浮點數嘅精度。表格轉換會將每一格保持為字串；長短唔一嘅行同非字串 JSON 格會被拒絕。圖像轉換只接受明確描述嘅點陣圖變體，重新開啟之後會比較每個 RGB 像素。ZIP 解壓只接受一個冇加密、儲存或者 deflate 壓縮嘅普通項目，拒絕絕對路徑同跳出資料夾嘅名稱，並驗證 CRC。建立 ZIP 時會將輸入存成 `payload.bin`，並驗證逐位元組解壓返嚟完全一樣。多項目解壓同 7z 未實作。

每個輸入上限係 16 MiB。PDF 合併將呢個上限套用喺所有來源位元組嘅總和。輸出上限係 64 MiB。PDF 傳輸封套上限係 24 MiB。圖像上限係 4,194,304 像素；結構化輸入有深度同項目數量上限。

## 變動披露同確認

每個轉接器嘅披露都會講清楚佢會改動或者略去乜嘢：換行、空白、引號、檔名、時間戳記、圖像解像度、色彩設定檔、中繼資料或者 PDF 結構。會損失資料，或者會改動中繼資料或編碼嘅轉接器，一定要明確確認先會加入檔案。呢啲包括 UTF-8 換行轉換、JSON 格式化、CSV/TSV 同 JSON 表格互轉、點陣圖轉換、ZIP 建立同解壓，以及每個 PDF 工具。十六進位同 Base64 編碼同解碼會保留每個位元組，唔使確認。

揀咗呢類轉接器，會顯示佢嘅披露、一行要求確認嘅說明同一個剔選框：*我已經睇過呢個轉換會改動或者略去嘅內容，並願意按呢啲變動轉換。* 未剔選之前，**加入來源檔案**同**加入來源資料夾**會喺開啟任何揀選器之前被拒絕，鍵盤焦點會移去個剔選框。取消剔選就會撤回確認。

確認會透過一個代碼綁定確切嘅披露（`acknowledgement_token()`：用轉接器 id、披露文字同佢嘅變動標記計出嚟嘅 16 個十六進位數字）。佢只喺今次使用期間有效，並會儲存喺每條已加入嘅佇列紀錄入面。佇列會拒絕冇相符代碼嘅加入（`disclosure_not_acknowledged`，唔會寫入任何紀錄），並略過代碼同現時披露唔再相符嘅已儲存紀錄（`disclosure_changed_since_acknowledgement`），所以更新改咗披露之後再繼續，都唔會用之前嘅確認嚟轉換。

## 隨附證明同程序界線

`LocalConverterPanel` 接受一個 `PackageProof`，入面有安裝目錄、相鄰嘅確切 `BambuStudio_converter_worker.exe`，以及套件建置收據入面預期嘅 SHA-256。共用整合會讀取 `converter-worker.sha256`，內容係 64 個小楷十六進位數字，後面可以有一個 LF。打包時必須由已暫存嘅工作程序重新產生呢個檔案，唔可以抄舊建置嘅摘要。

面板一開始會將所有轉接器列為不可用。非同步功能探測會先驗證工作程序位元組、啟動工作程序並確認佢嘅沙箱，之後先啟用核心轉接器。PDF 另外需要每個已編譯固定嘅 qpdf 12.4.2 runtime 檔案，同埋喺同一個沙箱入面成功初始化引擎。單靠相符嘅 manifest 永遠唔會啟用 PDF。

中介程序會鎖定工作程序檔案防止被取代，用零個 AppContainer 功能、明確嘅可繼承 handle 清單，同只包含必要作業系統目錄位置嘅隔離環境啟動佢。冇 PATH 查找、冇 shell 呼叫、唔會繼承 proxy，亦冇網絡功能。來源路徑同選項只會留喺私人中介程序；工作程序只收到有上限嘅位元組串流。Job object 將佢限制為一個程序、256 MiB 同 30 秒。取消會終止所屬嘅 job。工作程序本身會喺讀取要求之前驗證 `TokenIsAppContainer`。

官方 qpdf DLL 放喺 `tools/pdf`。轉換器 AppContainer 只需要嗰啲隨附 runtime 檔案嘅讀取/執行權限。永遠唔好授權存取來源文件、佇列紀錄或者無關嘅目錄。載入器會檢查已編譯嘅發佈雜湊值，保留唯讀 handle 防止被取代，並使用受限制嘅 DLL 搜尋。佢唔會執行 `qpdf.exe`。

## 耐久佇列同輸出發佈

佇列放喺應用程式嘅私人本機資料目錄。佢擁有一個獨佔嘅程序鎖，每個工作寫一條有上限嘅 JSON 紀錄。應用程式層面冇總檔案數上限。每頁最多 100 條紀錄，資料夾搜尋一次加入一個檔案。一次只會進行一個轉換，咁樣就有背壓，唔使將成個佇列收集入記憶體。

暫停會等目前嘅檔案做完，繼續會處理等緊嘅紀錄，取消會保留已完成嘅輸出。取消會推進一個耐久嘅世代編號，所以取消一百萬條等緊嘅紀錄唔會喺介面執行緒重寫一百萬個檔案。結果分頁會解讀已儲存嘅世代，重試會記錄佢明確嘅新世代。被拒絕嘅加入會有自己穩定嘅逐檔案結果。重新啟動之後永遠係暫停狀態。運行期間被中斷嘅紀錄會變成 `Recovery required`（需要復原）；佢永遠唔會被靜靜當成已完成，亦唔會自動重寫。明確重試需要目的地唔存在，同埋已加入嘅來源身分仍然有效。額外嘅 PDF 合併來源亦有耐久嘅大小/時間身分。中介程序喺發佈之前會再比較一次來源位元組。

加入同執行之前都會檢查目的地可用空間。輸出會寫入一個獨佔嘅相鄰暫存檔，清空緩衝、讀返出嚟比較，再用唔取代嘅原子操作發佈。分拆 PDF 嘅輸出係一個已驗證嘅 ZIP，所以都只有一個原子發佈界線。寫入失敗會移除自己嘅暫存輸出。已存在嘅目的地會被略過，包括預檢之後先同時建立嘅目的地。

結果 CSV 匯出包含可見嘅頁面行、只有檔名、狀態同穩定嘅結果代碼。一般診斷資料唔會包含文件內容或者來源路徑。私人佇列檔案為咗可以繼續工作，一定要保留使用者揀嘅路徑；佢哋唔可以同步、上載或者放入一般記錄檔。

## 原生整合

包含 `slic3r/GUI/LocalConverter/LocalConverterPanel.hpp`，喺一般分頁路由入面建立面板。提供已安裝套件收據同一個私人佇列目錄。編譯 `Converter.cpp`、`ArchiveAdapter.cpp`、`Worker.cpp`、`PdfAdapter.cpp`、`PdfRequest.cpp` 同 `PdfPackage.cpp`；連結現有嘅 miniz 目標，喺 Windows 再加 `bcrypt`、`userenv` 同 `advapi32`。只有已驗證嘅 qpdf SDK 標頭存在時先定義 `LOCAL_CONVERTER_WITH_PDF=1`。轉接器會動態解析 C API 符號，所以唔需要 qpdf 匯入程式庫。用同一個核心將 `WorkerMain.cpp` 編譯成獨立嘅工作程序。應用程式建置需要 `LOCAL_CONVERTER_QPDF_SDK`。`build.bat`、`build-installer.bat`、`OneClickBuildInstaller.cmd`、`build_win.bat` 同託管嘅 Windows 建置工作流程會喺 configure 之前暫存已驗證嘅 SDK；除咗 `build_win.bat`，其他都會將 runtime 放入套件嘅 `tools/pdf`（睇 [隨附 PDF 引擎](pdf-engine.md)）。

面板提供分類搜尋、PDF 選項搜尋、引導式輸入/輸出揀選器、PDF 頁面/旋轉/標題控制、明確排序嘅多檔案合併、資料夾搜尋、暫停/繼續/取消、分頁紀錄、全頁選擇/反選、重試已揀項目同匯出可見行。PDF 頁碼由 1 開始。

## 語言模式同搞笑程度

所有轉換器文字都跟英文、香港廣東話同雙語語言模式。面板自己嘅標籤、按鈕、搜尋同欄標題都係訊息目錄訊息。`Converter.cpp` 入面嘅登記表為分類、轉接器同來源類型名稱、變動披露、驗證方法、不可用原因同佇列狀態保留固定英文；嗰段英文就係訊息目錄來源，面板顯示時先翻譯。執行期間嘅診斷資料永遠唔會併入呢啲文字，而係以穩定嘅機器代碼另外放喺轉接器嘅 `detail`。

每個穩定結果代碼都有一句淺白說明（`Converter.cpp` 入面嘅 `result_message()`）。結果欄、詳情行同匯出嘅 `message` 欄會顯示翻譯好嘅說明，後面跟住代碼，例如 `The destination already exists. It was not replaced. (code destination_exists)`。以 Windows 錯誤編號結尾嘅代碼，例如 `isolated_worker_start_1114`，會按前綴共用一句說明，並保留編號。CSV 匯出會喺翻譯好嘅 `message` 旁邊保留穩定嘅 `state` 同 `result` 識別碼。

雙語模式下，狀態、詳情、頁面摘要同空白狀態行會先顯示英文再顯示廣東話，表格每一格會寫成 `English · 廣東話`。視窗標籤、按鈕同欄標題嘅第二語言由共用雙語裝飾器負責。

搞笑程度只會改變非事實性嘅行：指引行、空佇列同冇符合項目嘅狀態、未揀轉接器提示、工作程序檢查進度同完成行、轉換緊嘅行、停止摘要同匯出確認。每行都有認真、輕鬆同搞笑三個版本（`LocalConverterCopy.hpp`；第 1、2 級認真，第 3 級輕鬆，第 4、5 級搞笑），每個版本講嘅事實同數字都一樣，而英文同廣東話各自用返自己程度嘅版本。轉接器名稱、披露、原因、狀態、結果說明、限制同安全聲明都係事實，永遠唔會跟程度改變。

## 驗證同尚待整合嘅部分

獨立測試項目係 `tests/local_converter`，可以將 `LOCAL_CONVERTER_QPDF_SDK` 指向已驗證嘅 SDK 嚟 configure。佢會建置三個行為測試執行檔同真正嘅工作程序。核心測試冇工作程序路徑時報告 331 個斷言，有路徑時係 334 個，多出嘅三個係真正經雜湊驗證嘅 AppContainer 轉換；佢亦會檢查每個佢觸發嘅失敗都有結果說明、未確認或者確認唔相符嘅損失性加入會被拒絕，以及確認過時嘅紀錄會被略過而唔會有輸出。PDF 測試記錄咗 31 個類型斷言同 63 個封套斷言。PDF 要求測試可以接受可選嘅工作程序路徑同工作程序摘要參數，經真正嘅沙箱執行全部七個操作。

刻意嘅原始碼變異驗證咗：啟用未經證明嘅轉接器會令可用性斷言失敗，移除頁面上限會令有限分頁斷言失敗。兩個變異都已還原，還原後嘅實作重新編譯咗先至執行通過。並行、發佈前取消同爭用目的地嘅寫入都有行為測試覆蓋。

初次驗證時用嘅服務主機執行環境，喺 AppContainer 入面初始化唔到系統 `USER32.dll`（`1114`）。官方 qpdf 二進位檔會匯入呢個元件。已確認 Win32k 系統呼叫係啟用嘅。即時功能探測遇到呢個情況時，PDF 會保持停用。互動式隱藏桌面驗證仲未做；直接嘅類型測試唔能夠證明套件沙箱支援。

本地化由 `ui-md3/tests/local-converter-localization.test.mjs`（每個訊息目錄來源都有英文同廣東話條目、每個結果代碼都有說明、登記表文字喺顯示時翻譯、只有非事實性嘅行有語氣變化）同 `tests/local_converter_copy`（語氣階梯喺每個程度都保留事實同佔位符）固定。確認流程由 `ui-md3/tests/local-converter-acknowledgement.test.mjs`（變動標記同披露、佇列拒絕同略過，以及喺任何揀選器之前嘅剔選框關卡）固定。

原生面板仲未對照完整應用程式嘅 wx 依賴建置編譯，亦未喺打包好嘅應用程式入面試用，所以廣東話同雙語顯示、搞笑程度嘅版本，以及確認剔選框，仍然要喺嗰度睇到先算。逐元件外觀/鎖定選單、通知/紀錄整合、指令面板路由、完整批次操作覆蓋，同埋已記錄嘅語言/主題/顯示縮放截圖矩陣，仍然需要共用整合同執行期證據。單靠原始碼結果唔能夠證明呢啲特性。今次實作期間冇 Material Designer 建立/匯出工具；面板係用上面列出嘅現有套件元件組成，冇聲稱有設計工具交接。

轉換器冇 HTTP API。唔適用 Postman 集合。
